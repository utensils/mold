# iPhone + Android (apps/mobile, desktop/src/mobile)

Moved verbatim from the root CLAUDE.md; loaded only when working under the paths above.

**iPhone app** (`apps/mobile/src-tauri`, frontend entry in `desktop/src/mobile/`): a standalone thin Tauri crate, excluded from the root workspace so the desktop GPU/server dependency tree is never cross-compiled for iOS. It is always remote-only (`HostView.kind = "remote"`, `primary = false`) and owns the five Mold Studio destinations as four tabs plus a push screen: **Create**, a merged remote **Library**, **Models**, **Machines**/host detail, and a header-pushed Settings screen; a full-screen Advanced sheet hosts the sampler/negative/LoRA/format controls with an active-count badge; source media (image wells, first/last frames) lives in the primary Create stack, gated by the shared `sourceMediaPlan` policy. Reuse `desktop/src/lib` API types, explicit-target HTTP/SSE helpers, capability/request form, source fitting, gallery media, catalog, and theme logic; never import a desktop store that assumes a local **This device** engine.

Host metadata and selection live in WebView storage, but per-host API keys must remain in the native iOS Keychain under `com.utensils.mold.remote-api-key`. Host entry accepts LAN/IP/DNS/HTTPS and Tailscale MagicDNS names; Tailscale support is the existing tailnet/DNS path, not an embedded SDK. Native Apple DNS-SD discovers `_mold._tcp` under Local Network permission. Desktop and web Settings pair iPhone through authenticated `POST /api/pairing/sessions`: the QR carries an editable reachable base URL, exact instance ID, and a 256-bit random one-use ticket with a two-minute expiry, never the durable API key. Native camera scanning redeems only through `POST /api/pairing/claim`, verifies the returned instance, dedupes through the normal host path, and writes the returned key directly to Keychain; retain Bonjour and manual entry fallbacks. Authenticated image/video elements must use `POST /api/gallery/media-token` for a 15-minute, exact-path read ticket; never put the durable API key in a URL or buffer an entire video as the legacy fallback. LTX-2 guidance overrides use the shared Studio parser/serializer across web, desktop, and iPhone; native Advanced controls validate before queueing, restore metadata/templates, and keep untouched fields absent so pipeline constants remain authoritative.

Create shares the desktop capability/request contract, independently queues and cancels batch siblings, and keeps proportional resolution plus explicit Random/Fixed seed controls. On iOS, every validated one-shot or sequence submission holds a finite `UIApplication` background task across source preprocessing, placement fan-out when required, reference upload, and remote admission; release it after every one-shot sibling opens its response or the sequence-create POST returns, always end it on failure/cancellation/expiration, and rely on the remote host plus foreground reconciliation after acceptance rather than declaring a continuous background mode. Its generation target is a persisted policy (`mold.mobile.generate-target.v1`: host id | `auto` | `capable`) resolved by `desktop/src/mobile/generateTarget.ts`, and **Auto** / **Most capable** are offered only while at least two connected machines are reachable — one machine keeps the single-host behaviour exactly. One routing policy serves every surface: `studio/lib/hostRouting.ts` owns model-aware Auto, the CUDA > Metal > unknown capability ladder with GPU-name inference, target normalization, the fleet model union, and the frozen-host choice, and `desktop/src/lib/hosts.ts` plus `web/src/lib/hostRouting.ts` re-export it (binding only their own home host, which the phone does not have) rather than restating it. Generation never waits for a placement preview: pinned work submits directly, while an automatic policy chooses from cached model/queue/GPU telemetry and durably admits to that frozen host. `POST /api/generate/placement-preview` survives as the SEQUENCE planner, choosing by predicted completion including round trip for Auto and by captured `gpu_info.backend` for Most capable. The client gates on the MACHINE and never on the request — the durable protocol carries source media, LoRAs, `hdr_exr_dir`, identity photos, and H3's ordered references, so a per-trait client fence could only refuse work the server would take; the server's typed 4xx (`isDefiniteGenerationAdmissionRejection`) is the single authority for anything it cannot, and there is no second submission path. The model picker is the union across reachable machines with per-model availability. The winner is frozen into the same immutable route record the pinned path uses, so `mobileHostMatchesRoute`, prepared/quick expansion (which never re-route), and durable sequence recovery all keep the exact machine; a major-version `profileHashConflict` stops automatic routing instead of guessing, and a fleet where nothing can run the print queues nothing and names each machine. Its **Output** (One shot | Sequence) segmented field sits in the Create form stack above the model field — never a mode pair pinned above the form — and both outputs share one model picker (narrowed by `modelsForOutput`, naming `sequence_unsupported_reason` inline) and one set of size/fps/steps/guidance/seed fields read live at submit time via `buildChainRequest`; clips live in the shared `@studio` sequence draft, start at two required clips, and are separated by a 44pt seam pill whose bottom sheet hosts the shared `SeamEditor` (mobile's only fade-length control, clamped to `fade_frames_max`). Durable sequences stream over SSE with a 5s poll fallback and a wake re-sync, share ONE queue list with single prints, and restore on the exact snapshotted remote host; API keys remain Keychain-only. Generated stills open the full-screen viewer on tap. Library thumbnail sizing is the iPhone parity answer to the web/desktop slider, not a port of it: a scoped two-finger pinch over the grid moves a discrete 2–5 column count (default 3), persisted at `mold.mobile.galleryColumns.v1` — deliberately NOT the shared `mold.gallery.thumbnailSize.v1` pixel target, whose 220px default is meaningless at phone width and whose value must never be rewritten by a phone. Mobile Library metadata and thumbnails persist in IndexedDB so a saved grid paints before live refresh; records use the exact instance + filename + media version + rendition-tier identity, retain no full originals, cap each thumbnail at 2 MiB, and enforce 4,000-thumbnail/256 MiB global LRU limits. Unversioned media stays session-only, visible work wins over bounded prewarm, unchanged live rows reuse their URL, Trash preserves the cache, and permanent deletion or host removal evicts it. Library must keep native video playback and horizontal print navigation with explicit native **Copy image** / **Save photo** / **Save video** and **Use as prompt** / **Use as source** actions; image long-press keeps the native iOS Share/Save/Copy context menu, the 44pt **Select** control enters multi-select, and delete on iPhone, desktop, and web removes every matching copy from reachable connected devices while retaining and reporting failed-host copies. Persistent **New** visit state mirrors desktop, and desktop/mobile both badge upscaled images from saved provenance. Library organization (V3) is capability-gated per host (`capabilities.gallery.organize` / `.trash`): a 44pt Prints | Collections | Trash scope row (plain buttons that never capture the grid pinch), a scrolling ♥ Favorites/tag/host chip row, merged collection cards with drill-in and inline two-step rename/delete, a Trash scope with per-tile purge countdowns, Restore, two-step Delete forever, and a two-step Empty trash, and a viewer **Info** sheet (editable ≥16px title committed via PATCH — blank clears — ♥, tags with suggestions, collections checklist, and trash recovery); every mutation fans out per physical copy through the shared `planOrganizationFanout` to each host's exact Keychain-authenticated target with failures in a persistent inline banner (never a toast), and `desktop/src/mobile/libraryOrganization.ts` holds the pure mobile state helpers so `MobileApp.vue` stays an orchestrator. The Create form's Title field rides every mobile-built `GenerateRequest` as additive `title` (validated inline, inherited by batch siblings and prepared Batch N, restored by Use as prompt with a Library rename winning over the metadata stamp); it sits ABOVE the One shot | Sequence branch because the chain wire carries `title` for the stitched print too, so `printTitle` is a proxy over `form.title` rather than a second copy. Directly beneath it, the capability-gated **File under** group (`MobileFileUnder.vue`: a Tags row with the removable `from title` ghost chip, a Collection row pre-selecting — never creating — the slug-matched collection, both editing in `MobileLibrarySheet` bottom sheets, plus the `files as …~slug` preview) files the print at creation. Reducers are `@studio/lib/fileUnder` verbatim; `desktop/src/mobile/fileUnder.ts` owns only the phone's capability question — a pinned machine answers for itself, an automatic policy is satisfied by ANY reachable machine advertising `capabilities.gallery.organize`, and an unread snapshot hides the group. `stripTagHash` is applied to TYPED text only, never to a suggestion the host reported, and both entry points live in the same sheet, so each names its source explicitly. The ghost tag is derived rather than stored, so `applyFileUnderPolicy` strips the filing from any draft bound for a machine that cannot file; `chainFilingFields` puts title/tags/collection on the `POST /api/chain-jobs` body, and the stitched print is the only artifact filed. Host detail's capability-gated Library card edits that host's `gallery.trash_retention_days` through the first mobile `/api/config` client (`desktop/src/mobile/hostConfig.ts`; env-pinned keys render read-only) — retention is server-side, `mold.mobile.settings.v1` stays four local fields. Models Pull must immediately progress Connecting → Starting → Queued → Pulling N%, subscribe and reduce the opening download snapshot before POST, suppress duplicate POSTs, and retain the returned job-id association across catalog/source/display-name differences. Models browsing must self-heal: the family taxonomy and a failed catalog search re-drive whenever the browsed host's URL, key, or reachability changes, a failed reload keeps the last taxonomy instead of blanking it, and the family picker falls back to families observed in results/inventory (never to the rows currently on screen, which collapse to the active filter). Host detail owns telemetry, models-disk, queue, downloads, loaded models, and installed inventory; still-queued work has a 44pt two-step cancellation action routed to the exact Keychain-authenticated host, while running work remains non-cancellable.

Mobile settings persist at `mold.mobile.settings.v1`, default fresh installs to the Safelight theme (`theme: ThemeId` + `matchSystem`, the same six-theme contract as desktop; the pre-redesign `theme`/`themeFamily` pair migrates through `migrateLegacyTheme`) with Photos auto-save and "Tag new prints with their title" (`autoTagTitle`) enabled, preserve valid saved choices, and use shared `src/lib/theme.ts`; apply the theme before mount. `autoTagTitle` is absent on every install saved before File under and migrates to the on default; it is mirrored onto `GenerateForm.fileUnderAutoTag`, which the shared builder deliberately defaults to FALSE so a surface with no visible ghost chip can never auto-tag invisibly. Photos auto-save fetches completed stills from the authenticated host gallery and passes them to the native image-only Photos bridge without retaining generation base64; post-generation upscales save both original and upscaled images, while videos stay remote. About must keep an easily accessible external-browser link to the public policy at `https://utensils.io/mold/privacy`, whose source is `website/privacy.md`. The serialized `set_mobile_appearance` bridge must coalesce rapid changes and update UIKit traits/status-bar appearance to the final value. Preserve the iPhone interaction invariants: safe-area layout, 44pt controls, editable text at least 16px, `maximum-scale=1` / `user-scalable=no`, shell `touch-action: manipulation` and `overscroll-behavior: none`, with only the gallery viewer's scoped pan/swipe behavior reserved for navigation and the Library grid's scoped `touch-action: pan-y` pinch reserved for thumbnail sizing. iPad remains a responsive secondary target. **Identity photos are a phone surface too.** Create mounts the shared `@studio/components/IdentityPhotoWell.vue` (through `desktop/src/mobile/MobileIdentityWell.vue`) in the PRIMARY form beside the source wells — never inside the source-media plan, never in the Advanced sheet — gated on positive `supportsIdentity` knowledge only and hidden for Sequence output. A photo staged before a capability-losing model switch is PARKED: retained in the form, kept off the wire by `buildRequest`, Develop still enabled, rendered again the moment a qualified checkpoint returns. The photo is never fitted, cropped, or resized against the canvas and carries no `source_fit` provenance. `Identity strength` and `Identity start step` live in the full-screen Advanced sheet, feed its active-count badge, clear on its Reset while the attached face survives, and stay absent from the request until touched. Every refusal is inline beside the control and repeated in the Develop blocker — never a toast; prepared Batch N siblings inherit the whole partition and a prepared card is blocked (named stale work) when the partition becomes invalid. Automatic routing restricts candidates to machines whose own `/api/models[]` row advertises `supports_identity` and refuses a frozen winner that does not. The Library viewer's Info sheet lists identity provenance and opens for it even on a host with no organization capability; **Use as prompt** restores both knobs and re-attaches the photo from the shared content-addressed stash through `restoreIdentityPhoto`, disclosing a miss in the persistent inline status line. `desktop/src/mobile/identity.ts` holds the pure phone-shaped helpers so `MobileApp.vue` stays an orchestrator.

Devshell: `ios-dev` (zero-arg default boots an iPhone simulator — never a plugged-in phone; `MOLD_IOS_DEVICE` overrides, a device-name arg targets hardware) / `ios-run` / `ios-check` / `ios-build`; direct helper: `scripts/ios.sh` (`init`, `simulator` also exist). CI: `.github/workflows/ios.yml`; eligible successful `main` runs chain to `.github/workflows/testflight-ios.yml` (there is no cron). TestFlight exports must remain eligible for both internal and external groups — never set Apple's `testFlightInternalTestingOnly` export option to true. Automated release completion means App Store Connect `VALID` plus `Mold Internal` tester-membership verification; external groups then select that build for Beta App Review, and `testflight-ios-verify.yml` resumes an already uploaded exact bundle version. The Vite build must rename its separate source entry to `dist-mobile/index.html`, and `scripts/tests/ios-release-assets.sh` guards that entry and the opaque Apple icon catalog; regenerate icons with `scripts/generate-ios-icons.sh`. Release automation synchronizes the mobile crate/lockfile/Tauri config version; the archive build supplies its exact bundle build number. `apps/mobile/README.md` is the detailed maintainer reference.

**Android foundation** (`apps/mobile/src-tauri/gen/android`): generate and build Android from the SAME remote-only Tauri crate and `desktop/src/mobile` Vue surface as iPhone; never create a second product UI or import the desktop local-engine graph. `scripts/android.sh` and the dev-shell commands default Android Studio, SDK/NDK, Pixel 9 Pro Android 17 AVD, Gradle, Cargo, and Bun caches to `/Volumes/ExternalStorage/Android` (`MOLD_ANDROID_ROOT` overrides), pin NDK `27.0.12077973`, compile/target SDK 36, and minimum SDK 24. `apps/mobile/plugins` owns the Android-native bridge: API keys are AES-GCM encrypted with a non-exportable `com.utensils.mold.remote-api-key.v1` Android Keystore key and only ciphertext enters private preferences; native QR scanning redeems the same one-use pairing ticket and records client kind `android`; NSD discovers `_mold._tcp`; MediaStore, clipboard, and share intents provide native media actions; and system-bar insets keep the shared WebView clear of Android chrome. Identity acquisition reuses the shared Studio/mobile policy and well: Android's 48dp source sheet delegates to the native Photo Picker or a FileProvider camera URI without broad storage permission, verifies the 16 MiB provider size before reading, and lets the system back gesture dismiss the sheet; never fork identity gating, parking, request, routing, provenance, or reuse policy in Kotlin. `android-test` runs the native bridge instrumentation suite on an emulator. Path-classified Android CI builds a debug APK for relevant changes and runs the emulator only for Kotlin/generated-native changes. Release CI builds one signed ARM64/ARMv7 universal `Mold-android.apk` for every non-scheduled `main` and `v*` run, verifies it with `apksigner`, publishes it raw on the rolling Nightly and tagged releases, and includes it in `SHA256SUMS`; both channels share the long-lived signing identity and monotonic CI version-code scheme so sideloaded installs upgrade in place. Play publishing remains release work.
