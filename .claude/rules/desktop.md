# Desktop app (Tauri) invariants

Moved verbatim from the root CLAUDE.md; loaded only when working under the paths above.

Desktop gallery authority is singular: while its local server is running or its lifecycle is unresolved, native list/save/delete/media paths use authenticated HTTP (ticketed for media elements). Direct filesystem access is allowed only while the lifecycle mutex proves `LocalServer::Off`.

**Desktop app** (`desktop/`): Tauri 2 macOS/Linux/Windows app (Vue 3 + TS, **Mold Studio** design system — `docs/design/README.md` (lexicon, shell anatomy, component vocabulary) and the reference implementation `docs/design/mold-studio-desktop.dc.html` are the design source of truth; six named themes — Mocha (default), Safelight, Blueprint, Graphite, Porcelain, Nebula — each a complete `--mold-*` token map in `ui/tokens.css` selected by one `data-theme` attribute, with a **Match system** toggle that swaps to the paired light/dark theme through `THEME_PAIR` in `ui/theme.ts`; the Rust `AppSettings` stores `{ theme: ThemeId, match_system }` and migrates the old `{ theme, theme_family }` pair on the JSON value so a legacy `theme` can never fail the struct and drop saved hosts; shared primitives live in repo-root `ui/`, consumed by web, desktop, and iOS), package `mold-desktop` — its own cargo root, `exclude`d from the workspace. The desktop speaks the binding lexicon (`docs/design/README.md` §2; `desktop/src/lib/lexicon.test.ts` pins the destination words on the router, sidebar, palette, and native menu plus the inspector's seed labels — view copy is reviewed by hand): the sidebar's destinations are **New image** (⌘1, `/create` — sequence authoring lives inline: the inspector's **Output** (One shot | Sequence) card swaps the composer for the clip timeline; there is no `/create/chain` route, and legacy chain URLs permanently redirect to `/create?output=sequence`), **Queue** (⌘2, `/queue`), **My images** (⌘3, `/library`, Recent settings drawer via `?panel=history`), **Styles** (⌘4, `/models`), **Machines** (⌘5, `/machines`, master/detail with the machine pane at `/machines/:id` and Rent a GPU at `/machines/runpod` as nested children so the titlebar keeps saying Machines), and **Settings** (⌘,) — with permanent redirects from every legacy route (web and the phone keep the five-workspace names until their own redesign). The shell is the README §3 anatomy: a 44px unified toolbar (`TitleBar.vue`: traffic lights, sidebar toggle, history, mono title + `useShellSubtitle` sentence, ⌘K, bell), a 270px sidebar (`Sidebar.vue`: MAKE / SETUP nav, the target-machine card from `stores/hostStatus.ts`, and the queue itself as `QueueRail.vue` — work in progress is context, not content), a 40px per-view toolbar, a 26px `StatusBar.vue` (machine · VRAM · queue · key hints), and every fixed-height chrome piece `shrink-0` so the canvas absorbs slack. The kit carries the pieces every view was re-declaring — `.ms-toolbar-button` (26px; `--on`, `--accent`, `--danger`, `--danger-hover`) and `.ms-group-label` in `ui/kit.css`, `SegmentedControl`'s `inline` mode for tabs with a mono count, `ModalPanel`'s header block — and `desktop/src/styles/tokens.legacy.test.ts` refuses the retired token vocabulary anywhere in desktop, `ui/`, or `studio/`. **Settings** is a 200px jump nav over always-open lexicon sections (`SECTIONS` in `lib/settingsSchema.ts` — Look, Defaults for new images, Write more for me, Machines, Saving pictures & clips, My images & trash, Style licences, Phone pairing, Speed & memory, Accounts & tokens, Profiles, Advanced, Updates & about; no accordions), where search narrows the nav and the page together and `?section=` jumps (`about` folds into `updates`). It reuses a running local `mold serve` on :7680 or embeds an authenticated, wildcard-bound, mDNS-advertised `mold-ai-server` (`metal` on macOS, `cuda` on Linux and x64 Windows; all off by default so tests are CPU-only); that built-in engine is permanently the app's internal primary (**This device**) — remote servers are only ever list entries, never a primary the app switches to (`settings::migrate_remote_primary` re-homes old remote-primary installs on boot: mode→local, ex-primary becomes a connected host, key moves to its per-host slot, generation pinned to it). Local and remote use one HTTP+SSE wire contract. Platform chrome/bundling lives in `tauri.{macos,linux,windows}.conf.json`; Linux provides `mold-desktop` (sm_89), `mold-desktop-sm120`, and an AppImage from `desktop-build`, Windows bundles NSIS, and in-app updates remain macOS-only. **Windows is a full desktop target with two named absences, never silent degradation.** The devshell does not run there, so `scripts/windows.ps1` (`doctor`/`setup`/`dev`/`ui`/`check`/`test`/`build`/`clean`) is the peer of the `desktop-*` commands and resolves the feature recipe per machine (CPU-only by default; `cuda` on an x64 host with a toolkit, `pulid` when protoc is on PATH; `MOLD_WINDOWS_FEATURES` / `MOLD_WINDOWS_CUDA` / `MOLD_WINDOWS_NO_PULID` override). The `mp4` feature is OFF on Windows through a `cfg(not(windows))` dependency entry: `fdk-aac-sys`'s `FDK_archdef.h` knows only GCC/Clang architecture macros and falls through to a `#warning`, which MSVC raises as the fatal C1021 on x64 and ARM64 alike, so video renders and muxes normally and only a generated AAC track is refused by name. `.cargo/config.toml` enables `fullfp16` for `aarch64-pc-windows-msvc` (`gemm-common`'s inline `fmla v.8h` needs it and it is not baseline there) and lives in the ROOT because cargo discovers config from the current directory, never from `--manifest-path`. Windows notifications go through `tauri-winrt-notification` for its `on_activated` callback so a click routes to the same `activate` the macOS delegate and Linux XDG handle reach. `.gitattributes` pins the working tree to LF on every platform — git's default `core.autocrlf` on Windows checks it out as CRLF, which prettier rejects for every file and which invalidates every `#!/usr/bin/env bash` shebang. It also owns native-only integrations: image clipboard/context menus, a unified multi-host gallery with the same persisted Lightroom-style top-bar thumbnail-size slider as web (every connected host + this device merged into one grid — filter chips, per-tile host badges, per-origin delete/save/reveal, host-keyed media blob cache; no separate IPC bucket — the local primary's `/api/gallery` is this device's gallery; the All view collapses cross-host copies of one print by filename, and by seed+byte-size identity for legacy copies — auto-saved remote outputs keep the origin's gallery filename and recorded metadata via the complete event's additive `filename`/`metadata` fields), persistent 80–130% webview scaling, a persisted left-edge-resizable Create settings inspector (280–480 px, 340 px default, double-click reset) whose Advanced toggle expands capability-gated, always-open icon sections inline below the simplified essentials without covering the canvas, file-backed app secrets (owner-only `secrets.json` under app data — including the persistent `desktop-local-api-key`; deliberately NOT the macOS Keychain, whose prompts users found obnoxious; don't reintroduce `keyring`), a remembered-hosts MRU with per-host API keys (`remote-api-key.<host-id>`; identity stays the URL slug, but entries dedupe by the server's instance UUID — `/api/status.instance_id`, mDNS `id` TXT — with display names from the server hostname, so one box reached by hostname/mDNS/IP collapses to one row), host management living in the **Machines** workspace (a 326px list: This device first, connected remotes, billing pods with their cost meter, Remembered, On your network, and the Rent-a-GPU offer; landing on `/machines` opens the machine the shell already talks about; **Connect a machine** is ONE dialog — the machines found on the network, or a typed address, an API key when the machine asks for one, and "Make images here from now on" — never a stepped wizard; Settings keeps only a Machines doorway), boot-time reconnect of every host in `connectedHostIds` (unreachable hosts stay listed as errored rows the status poll self-heals), the machine pane at `/machines/:id` (the README §4 toolbar — dot · mono name · one sentence of hardware, address, version, uptime · Make images here · Rename · Open web UI · Disconnect · Forget… — then **Right now** as one tile per meter (graphics memory, processor, system memory, disk for styles), **Loaded and ready** chips, **Waiting on this machine**, the compute plan, **Storage** beside **Downloads here**, and **Styles on this machine** on the shared row; a **Storage** card — that host's own `gallery.trash_retention_days` select via `lib/api/hostConfig.ts` plus "Prints in trash: N · Empty trash" behind the plain shared `ConfirmDialog`, hidden when the host's capabilities lack `gallery.trash`), a single unified **Styles** view (**Ready to use | Browse more** in the 40px view toolbar with the kind filter (All · Pictures · Clips via `?type=`) and Filter…; Ready to use opens with a disk-used-by-styles meter — one segment per family, each style's own weights so shared helpers never count twice — and rows on the shared `ModelTableRow` (name stacked over the mono id, a plain note, machines as dot + mono name; `isOpaqueModelId` keeps a Civitai install id off every title) with Load / Unload / Get it inline and the page link + **Remove from disk…** (plain `ConfirmDialog`) behind ⋯; Browse more keeps the one merged live-catalog feed with ready rows deduped by name, machine-tagged, sorted first, source chips All/HuggingFace/Civitai, the NSFW tag + include checkbox, and **Get it** as the one acquisition verb (`catalogPullLabel(info, "Get it")`; the phone keeps Pull); the download banner reads as a sentence with the CLI progress line — bytes, `rateByJob`, eta — beside it, pinned above both tabs), multi-host queueing (jobs carry per-host API targets and the Create view waits for the complete per-host `/api/models` union before showing the empty state, then routes via model-aware Auto/least-busy — hosts that already have the selected model win — a sticky pick, or "Most capable" (`generateTargetHost = "capable"` sentinel: backend CUDA > Metal > unknown, then VRAM, then queue, using the additive `gpu_info.backend` status field with GPU-name inference for older servers)), and RunPod pod/network-volume provisioning. **My images organization (V3 "Shelf"):** the header is segmented **Everything | Albums | Trash** (web keeps Prints | Collections | Trash) — Prints keeps the grid plus a filter-chip row (♥ Favorites · tag chips · host chips), Collections is a shelf of cards with a drill-in breadcrumb, Trash is a grid with the retention banner, per-tile "Purges in N d", Restore / Delete forever, and header Empty trash — and editing (title, ♥, tags, "In collections") lives in the Lightbox aside; there is NO typed-phrase confirmation anywhere (Empty trash / Delete forever use the plain shared `ConfirmDialog`). Organization state is per host in that host's `mold.db`, merged client-side by `studio/lib/libraryOrganization.ts` (collections by slug, tags case-insensitively) and mutated through `studio/api/galleryOrganization.ts` fan-out; a host whose `capabilities.gallery` lacks `trash`/`organize` hides every organization control and keeps today's hard-delete wording. Trash obeys the singular-authority rule: while the local server runs, this device's delete/trash-list/restore/delete-forever IPC (`local_gallery_delete` → trash, `local_gallery_trash_list`, `local_gallery_restore`, `local_gallery_delete_forever`) routes over authenticated HTTP; only a proven `LocalServer::Off` moves files to `<output_dir>/.trash/` with a `mold_db::trash` tombstone + row flag (no DB ⇒ the old `remove_file`), and `mold-local:` media resolves trashed files into `.trash/`. Retention is the host's own `gallery.trash_retention_days` (`0` = forever): Settings ▸ Library edits this device's through the settings store; Machines ▸ host ▸ Storage edits a remote's. Print titles: the Create header's "Untitled print / sequence" is an inline-editable `GenerateForm.title` (click; Enter/blur commits, Escape reverts; `validatePrintTitle` ≤ 120 chars, no control chars) that `buildRequest` ships as additive `GenerateRequest.title` on every one-shot, Batch N sibling, and prepared variation; generating keeps it (siblings share the name) and only ⌘N clears it; Reuse settings restores `metadata.title`; Save/Export suggest `{title-slug}__{model}__s{seed}.{ext}` via `lib/gallery/saveName.ts` (the shared port of `mold_core::download_file_name`) while the gallery filename never changes, and a sequence puts `title` on the `POST /api/chain-jobs` body, where it names the stitched print alone. **File under** is the capability-gated Create-inspector group between the essentials and Advanced (`buildRequest` for prints, `chainFilingFields` for sequences): a removable `{slug} · from title` ghost chip, typed tags autocompleted from every connected machine's counts, and a collection row that pre-selects — never creates — the slug-matched collection, with an inline **New collection…** that only records a name until develop. It rides one-shots, Batch N siblings, prepared variations, and the stitched sequence print, is restored by Reuse settings, and hides whole when `capabilities.gallery.organize` is not true; Settings ▸ Library's **Tag new prints with their title** (`library.autoTagTitle`, localStorage via `libraryPrefs`) governs the ghost chip only. Devshell: `desktop-dev` / `desktop-build` / `desktop-release` / `desktop-check` / `desktop-test` / `desktop-ui` (Windows: `scripts/windows.ps1`; the frontend lockfile refresher is the repo-root `frontend-bun-lock`); CI: `.github/workflows/desktop.yml`, whose `desktop-windows` job runs Clippy, tests, signing contracts, and the NSIS installer after merge on `main` (or on manual/nightly workflows), never on pull requests; PR-native feedback comes from the macOS desktop gate. Its version tracks the workspace version (synced automatically on the release PR by `scripts/release/sync-release-pr.sh`; `tauri.conf.json` has no version field on purpose). Gotcha: the tauri dev watcher does not rebuild on `crates/` changes — relaunch `desktop-dev` to pick up engine changes. In Vue stores, `reactive()`-wrap any object mutated from SSE/closure callbacks (raw-object mutations bypass proxy traps and freeze the UI).

Desktop Linux distribution additionally includes `mold-desktop-sm86`; B200 remains a remote-server target and has no sm100 desktop package. Desktop Settings exposes the effective `MOLD_HOME` with a typed path and native folder picker. An optional migration copies the complete current root through an atomic sibling staging directory, preserves the old root, and relaunches only after the destination is ready; the shared bootstrap choice is resolved by `mold-core` before config, SQLite, logging, gallery, and server initialization so every local surface retains the same `Config::mold_dir()` authority.

**Desktop updater:** signed release builds support persisted **Stable** and **Nightly** channels. Startup and menu/Settings checks are check-only; an available update is announced in persistent app chrome and by a native notification while backgrounded, and installation requires the user's explicit **Update and restart** action. Stable reads the public `mold-desktop-stable.json` manifest from the latest tagged release; Nightly reads `mold-desktop-nightly.json` from the rolling `latest` prerelease, which `.github/workflows/desktop.yml` rebuilds only after the frontend and Rust gates pass for a desktop-relevant `main` commit. Before touching the installed app, Tauri verifies the Minisign signature and Mold fully extracts the archive to temporary storage, binds its bundle ID/version to the manifest, runs strict Apple code-signature and Gatekeeper checks, validates the current app identity and install location, and proves the app's parent directory is replaceable. Only then does Mold atomically exchange the staged and installed bundles with macOS `RENAME_SWAP` and restart. There is deliberately no post-launch watchdog, probation, or Mold-owned rollback; the update either passes preflight and installs or fails while the running version remains in place. Do not add a silent downgrade comparator: selecting Stable from a newer Nightly waits for a later stable version. Distribution CI requires `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` in addition to the Apple signing/notarization secrets, verifies signatures against the checked-in public key, and retains ten Nightly desktop generations. The updater private key must have controlled offline backup and must never enter the repo or logs; losing it strands installed clients, and rotation must first be delivered by an update signed with the existing key.

**Desktop Library performance invariant:** the grid is near-native at 1 000+ prints because nothing per tile walks the gallery. `desktop/src/stores/gallery.ts`'s `organizationIndex` / `bucketIndex` getters compute each logical print's organization union and cross-host copies ONCE per data change (`organizationOf`, `locationsOf`, `existsLocally`, `rowOf` all read them; `locationsIn` is the same filename-or-identity-within-window answer the old full scan gave, off the index), rows are `markRaw` immutable snapshots replaced through `patchRow` — never mutated in place, which would notify nothing — and a 304 poll skips the assignment. `LibraryView` renders ONE flat print-keyed absolutely positioned tile layer from per-tile `TileModel`s so a slider drag or resize moves tiles instead of remounting `AuthedMedia`; `studio/lib/thumbnailScheduler.ts` dispatches from per-(priority, host) FIFOs in O(hosts). Thumbnails persist in `desktop/src-tauri/src/thumbnail_cache.rs` (`<app_data>/thumbnail-cache/v1`, key = origin + filename + `media_version` + tier, NEVER the API key; 512 MB / 20 000 files LRU), prepared through `prepare_gallery_thumbnail` and displayed through the async `mold-thumb://` protocol that only reads the cache, so JS holds no bytes for a tile and a cold launch touches no host; with the engine Off, this device's tiles are rendered in-process through `mold_server::thumbnails` and never the full-size file. Every guard is an OPERATION COUNT against a budget (`studio/lib/galleryPerfBudget.ts`): `gallery.perf.test.ts`, `LibraryView.perf.test.ts` (real virtualizer, 2 000 prints), the scheduler drain test, and `cached_thumbnail_performs_zero_fetches` — add to them, never loosen them. Web and the phone have no native disk: `studio/lib/thumbnailPersistentCache.ts` is the shared Cache API store (secure contexts only — a plain-`http://` LAN origin gets `null` and keeps the memory LRU; keyed host + filename + `media_version` + tier, never without a version), `web/src/lib/galleryMedia.ts` reads it for authenticated hosts, the phone already persists through `storeCachedGalleryMedia`, and `thumbnailRenditionQuery` (`?size=256|512&fmt=jpeg`, 512 at DPR ≥ 1.5) is the one rendition policy every surface appends — an older server ignores it and answers its 256 px PNG, so no client may branch on the reply's format.

**Desktop model-library invariant:** the Installed shelf and download progress are all-connected-host views, host detail mirrors the selected host's pulls, and built-in manifest variants take precedence over ambiguous multi-checkpoint Hugging Face repositories so a Pull targets one runnable model rather than an aggregate repository. Remembered hosts in `connectedHostIds` are attempted immediately on launch in parallel with This Mac; an explicitly disconnected host stays remembered but is excluded from reconnects and every all-host operation until the user reconnects it.
