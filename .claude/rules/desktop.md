# Desktop app (Tauri) invariants

Moved verbatim from the root CLAUDE.md; loaded only when working under the paths above.

Desktop gallery authority is singular: while its local server is running or its lifecycle is unresolved, native list/save/delete/media paths use authenticated HTTP (ticketed for media elements). Direct filesystem access is allowed only while the lifecycle mutex proves `LocalServer::Off`.

**Desktop app** (`desktop/`): Tauri 2 macOS/Linux/Windows app (Vue 3 + TS, **Mold Studio** design system — `docs/design/README.md` (lexicon, shell anatomy, component vocabulary) and the reference implementation `docs/design/mold-studio-desktop.dc.html` are the design source of truth; six named themes — Mocha (default), Safelight, Blueprint, Graphite, Porcelain, Nebula — each a complete `--mold-*` token map in `ui/tokens.css` selected by one `data-theme` attribute, with a **Match system** toggle that swaps to the paired light/dark theme through `THEME_PAIR` in `ui/theme.ts`; the Rust `AppSettings` stores `{ theme: ThemeId, match_system }` and migrates the old `{ theme, theme_family }` pair on the JSON value so a legacy `theme` can never fail the struct and drop saved hosts — and `settings::load` recovers PER KEY, so a value this build cannot read (an update channel or connection mode a newer nightly wrote, then an older build or a dev build sharing the same app data reads it back) falls back alone while every other key stays, a list keeps every element that reads (one malformed saved machine never forgets the others), and `load_reporting` names the keys that fell back so the boot-time remote-primary migration is withheld when `mode` or `remoteUrl` was a fallback rather than the user's value (`migration_premise_intact`); a document that is not a JSON object is kept as owner-only `settings.json.invalid` rather than overwritten. Never let `load` answer a parse failure with whole-struct defaults: the next save persists them, which is exactly how a stale dev build moved a Nightly install back to Stable and forgot every machine on 2026-09-03; shared primitives live in repo-root `ui/`, consumed by web, desktop, and iOS), package `mold-desktop` — its own cargo root, `exclude`d from the workspace. The desktop speaks the binding lexicon (`docs/design/README.md` §2; `desktop/src/lib/lexicon.test.ts` pins the destination words on the router, sidebar, palette, and native menu plus the inspector's seed labels — view copy is reviewed by hand): the sidebar's destinations are **New image** (⌘1, `/create` — the view toolbar's **Still picture | Short clip | 3-D object** control is the ONE output switch, emitting `set-output` into the inspector's `setOutputMode`; the inspector carries no second one. Sequence authoring lives inline: choosing Short clip raises the clip TIMELINE above the composer, which stays mounted and is the ONE Generate button for both modes — in clip mode it carries the SELECTED SCENE's words (two-way with the draft store's active scene), reads "Scene N — describe what happens next", counts "Make 1 clip", and ⌘↩ submits the chain; the one-shot prompt's provenance, its quick rewrite, and its ↑/↓ history stand down there because those words belong to a scene, not to the form. `SequenceComposer.vue` is therefore the timeline alone — transport (a 26px accent play/pause driven by the rendered-clip player, mono `0:06 / 0:20`, "Add a scene"), ruler, the scenes lane, the playhead, the selected scene's Length picker, the seam editor, and one mono readout — and it reports its own refusal up through `update:blockedReason` rather than holding a second primary action. The lane is `desktop/src/components/create/SceneLane.vue`, desktop-only: every block is `flex: <seconds> 1 0`, so a block is as wide as the time it plays and the lane always FITS its width — there is nothing to scroll, which is the whole difference from the shared `ui/components/ClipRail.vue` filmstrip web still uses. A block's title is the scene's own words, its poster sits behind at 34%, the seam floats above the join, and only the selected block carries the 9px trim grip, whose drag snaps to the same frame grid (`8k+1`, `4k+1` for wan) the Length picker offers. Desktop says "scene" everywhere, aria included; there is no `/create/chain` route, and legacy chain URLs permanently redirect to `/create?output=sequence`), **Queue** (⌘2, `/queue`), **My images** (⌘3, `/library`, History as an inline column via `?panel=history`), **Styles** (⌘4, `/models`), **Machines** (⌘5, `/machines`, master/detail with the machine pane at `/machines/:id` and Rent a GPU at `/machines/runpod` as nested children so the titlebar keeps saying Machines), and **Settings** (⌘,) — with permanent redirects from every legacy route (web and the phone keep the five-workspace names until their own redesign). The shell is the README §3 anatomy: a 44px unified toolbar (`TitleBar.vue`: traffic lights, sidebar toggle, history, mono title + `useShellSubtitle` sentence, ⌘K, bell), a 270px sidebar (`Sidebar.vue`: MAKE / SETUP nav, the target-machine card from `stores/hostStatus.ts`, and the queue itself as `QueueRail.vue` — work in progress is context, not content), a 40px per-view toolbar, a 26px `StatusBar.vue` (machine · queue · VRAM · RAM · downloads on the left, then the `⌘↩ Generate · ⌘K Search · Space Pause queue` key hints on the right), and every fixed-height chrome piece `shrink-0` so the canvas absorbs slack. Space is the shell's ONE un-modified chord (`resolveBareShellShortcut`): it toggles the display host's queue pause, and stands down inside a field, on a focused control, under any `aria-modal` overlay, and on `/library`, where Space is Quick Look. It reuses a running local `mold serve` on :7680 or embeds an authenticated, wildcard-bound, mDNS-advertised `mold-ai-server` (`metal` on macOS, `cuda` on Linux and x64 Windows; all off by default so tests are CPU-only); that built-in engine is permanently the app's internal primary (**This device**) — remote servers are only ever list entries, never a primary the app switches to (`settings::migrate_remote_primary` re-homes old remote-primary installs on boot: mode→local, ex-primary becomes a connected host, key moves to its per-host slot, generation pinned to it). Local and remote use one HTTP+SSE wire contract. Platform chrome/bundling lives in `tauri.{macos,linux,windows}.conf.json`; Linux provides `mold-desktop` (sm_89), `mold-desktop-sm120`, and an AppImage from `desktop-build`, Windows bundles NSIS, and in-app updates remain macOS-only. **Windows is a full desktop target with two named absences, never silent degradation.** The devshell does not run there, so `scripts/windows.ps1` (`doctor`/`setup`/`dev`/`ui`/`check`/`test`/`build`/`clean`) is the peer of the `desktop-*` commands and resolves the feature recipe per machine (CPU-only by default; `cuda` on an x64 host with a toolkit, `pulid` when protoc is on PATH; `MOLD_WINDOWS_FEATURES` / `MOLD_WINDOWS_CUDA` / `MOLD_WINDOWS_NO_PULID` override). The `mp4` feature is OFF on Windows through a `cfg(not(windows))` dependency entry: `fdk-aac-sys`'s `FDK_archdef.h` knows only GCC/Clang architecture macros and falls through to a `#warning`, which MSVC raises as the fatal C1021 on x64 and ARM64 alike, so video renders and muxes normally and only a generated AAC track is refused by name. `.cargo/config.toml` enables `fullfp16` for `aarch64-pc-windows-msvc` (`gemm-common`'s inline `fmla v.8h` needs it and it is not baseline there) and lives in the ROOT because cargo discovers config from the current directory, never from `--manifest-path`. Windows notifications go through `tauri-winrt-notification` for its `on_activated` callback so a click routes to the same `activate` the macOS delegate and Linux XDG handle reach. `.gitattributes` pins the working tree to LF on every platform — git's default `core.autocrlf` on Windows checks it out as CRLF, which prettier rejects for every file and which invalidates every `#!/usr/bin/env bash` shebang. There is deliberately no "Save every result" toggle and no "took 4.0s" on a Recent row: neither has a backend (`OutputMetadata` records no generation time), and the desktop composer has no style-preset strip — the word "Style" belongs to the model.

**Embedded engine stop is bounded, and its boot test reads what it requests.** `start_engine_inner` calls `mold_server::bound_http_drain(server::HTTP_DRAIN_GRACE)` before `run_server` because Axum's graceful shutdown waits for every in-flight request and the webview is a client the app does not control (a paused video stops draining its socket; a request whose body never arrives stays in flight forever); after the grace the engine gives up on them, and the runtime drop in `server.rs` is what closes those connections. `HTTP_DRAIN_GRACE` must leave `ENGINE_STOP_BUDGET` room for the dozen shutdown steps after the drain (a compile-time assert pins the ratio); the stop command and app exit pass `ENGINE_STOP_BUDGET`, and changing Mold home waits twice it. The standalone server keeps its unbounded drain behind `MOLD_SHUTDOWN_ABORT_SECS`, which ends the process. In `desktop/src-tauri/tests/engine_boot.rs` every response is READ before shutdown: `/api/models` is over a megabyte, and a response left unread is a response the engine is still writing once the loopback buffers fill — whether they fill was up to the kernel's window autotuning, which is the coin flip that skipped the desktop nightly for days (#1582). `a_client_that_stalls_cannot_hold_the_engine_open` pins the bound with a request whose body never arrives.

Desktop Linux distribution additionally includes `mold-desktop-sm86`; B200 remains a remote-server target and has no sm100 desktop package. Desktop Settings exposes the effective `MOLD_HOME` with a typed path and native folder picker. An optional migration copies the complete current root through an atomic sibling staging directory, preserves the old root, and relaunches only after the destination is ready; the shared bootstrap choice is resolved by `mold-core` before config, SQLite, logging, gallery, and server initialization so every local surface retains the same `Config::mold_dir()` authority.

**Desktop updater:** signed release builds support persisted **Stable** and **Nightly** channels. Startup and menu/Settings checks are check-only; an available update is announced in persistent app chrome and by a native notification while backgrounded, and installation requires the user's explicit **Update and restart** action. Stable reads the public `mold-desktop-stable.json` manifest from the latest tagged release; Nightly reads `mold-desktop-nightly.json` from the rolling `latest` prerelease, which `.github/workflows/desktop.yml` rebuilds only after the frontend and Rust gates pass for a desktop-relevant `main` commit. Before touching the installed app, Tauri verifies the Minisign signature and Mold fully extracts the archive to temporary storage, binds its bundle ID/version to the manifest, runs strict Apple code-signature and Gatekeeper checks, validates the current app identity and install location, and proves the app's parent directory is replaceable. Only then does Mold atomically exchange the staged and installed bundles with macOS `RENAME_SWAP` and restart. There is deliberately no post-launch watchdog, probation, or Mold-owned rollback; the update either passes preflight and installs or fails while the running version remains in place. Do not add a silent downgrade comparator: selecting Stable from a newer Nightly waits for a later stable version. Distribution CI requires `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` in addition to the Apple signing/notarization secrets, verifies signatures against the checked-in public key, and retains ten Nightly desktop generations. The updater private key must have controlled offline backup and must never enter the repo or logs; losing it strands installed clients, and rotation must first be delivered by an update signed with the existing key.

**Desktop Library performance invariant:** the grid is near-native at 1 000+ prints because nothing per tile walks the gallery. `desktop/src/stores/gallery.ts`'s `organizationIndex` / `bucketIndex` getters compute each logical print's organization union and cross-host copies ONCE per data change (`organizationOf`, `locationsOf`, `existsLocally`, `rowOf` all read them; `locationsIn` is the same filename-or-identity-within-window answer the old full scan gave, off the index), rows are `markRaw` immutable snapshots replaced through `patchRow` — never mutated in place, which would notify nothing — and a 304 poll skips the assignment. `LibraryView` renders ONE flat print-keyed absolutely positioned tile layer from per-tile `TileModel`s so a slider drag or resize moves tiles instead of remounting `AuthedMedia`; `studio/lib/thumbnailScheduler.ts` dispatches from per-(priority, host) FIFOs in O(hosts). Thumbnails persist in `desktop/src-tauri/src/thumbnail_cache.rs` (`<app_data>/thumbnail-cache/v1`, key = origin + filename + `media_version` + tier, NEVER the API key; 512 MB / 20 000 files LRU), prepared through `prepare_gallery_thumbnail` and displayed through the async `mold-thumb://` protocol that only reads the cache, so JS holds no bytes for a tile and a cold launch touches no host; with the engine Off, this device's tiles are rendered in-process through `mold_server::thumbnails` and never the full-size file. Every guard is an OPERATION COUNT against a budget (`studio/lib/galleryPerfBudget.ts`): `gallery.perf.test.ts`, `LibraryView.perf.test.ts` (real virtualizer, 2 000 prints), the scheduler drain test, and `cached_thumbnail_performs_zero_fetches` — add to them, never loosen them. Web and the phone have no native disk: `studio/lib/thumbnailPersistentCache.ts` is the shared Cache API store (secure contexts only — a plain-`http://` LAN origin gets `null` and keeps the memory LRU; keyed host + filename + `media_version` + tier, never without a version), `web/src/lib/galleryMedia.ts` reads it for authenticated hosts, the phone already persists through `storeCachedGalleryMedia`, and `thumbnailRenditionQuery` (`?size=256|512&fmt=jpeg`, 512 at DPR ≥ 1.5) is the one rendition policy every surface appends — an older server ignores it and answers its 256 px PNG, so no client may branch on the reply's format.

**Desktop model-library invariant:** the Ready-to-use shelf and download progress are all-connected-host views, host detail mirrors the selected host's downloads, and built-in manifest variants take precedence over ambiguous multi-checkpoint Hugging Face repositories so Get it targets one runnable model rather than an aggregate repository. Remembered hosts in `connectedHostIds` are attempted immediately on launch in parallel with This Mac; an explicitly disconnected host stays remembered but is excluded from reconnects and every all-host operation until the user reconnects it.
