# Qwen Image 2.1 references, canvas and transparency

Moved from the root CLAUDE.md; loaded only when working under the paths above. Engine execution-path and precision rules stay in `inference.md`.

- **Qwen Image 2.1 references `Replace`, and its canvas and transparency are profile contracts.** `reference_images_for_recipe("qwen-image21")` advertises up to `QWEN_IMAGE21_MAX_REFERENCE_IMAGES` (10) ordered `edit_images`, `source_relation: replaces`, no target image, plus two additive fields: `formats` (`png`/`jpeg`/`webp`; empty = PNG/JPEG, an older server) and `canvas: last-reference` — a CLIENT rule (the CLI with neither `--width` nor `--height`, `studio/lib/referenceCanvas.ts`), because `width`/`height` are required and admission can never tell a chosen size from a default. Every surface derives it through ONE function, `validation::last_reference_canvas` (Studio mirror `lastReferenceCanvas`), fed the EXIF-oriented size (below): the last reference's aspect at upstream's fixed 1024² (`LAST_REFERENCE_CANVAS_AREA`, never a host's configured default, so client and server advisory agree), clamped into the recipe's `resolution` bounds — a deliberate divergence, since upstream caps nothing and a >7.3:1 panorama would derive a width admission refuses. The manifest's `source_image` is the `None` passthrough, per the rule above. `capabilities.transparency` (`transparency_for_recipe` / `validate_transparency_against`, both doors, byte-equal refusals; absent = older server) gates `transparent_background`, which only `Some(true)` carries (`false` normalizes to absent). The model card's RGBA recipe (`mold_core::transparency`, whose two sentences the corpus test pins verbatim) is applied by the ENGINE to the positive prompt and never stored — Reuse would double-wrap it and the expander would rewrite it. The alpha rule is exact, not a threshold: `image::alpha_output_for_request` keeps RGBA iff the toggle is on OR a reference has a pixel below 255, else drops it to RGB byte-identical to v0.32 (opaque renders measure edge alpha 204–252, so "any alpha < 255" would make every render RGBA); a kept alpha meeting JPEG composites over white with a request warning. A reference is decoded ONCE, by `img_utils::decode_reference_rgba`, for both the conditioning and that alpha question (an undecodable alpha-capable reference is an error, never "opaque"): bounded by `mold_core::reference_image` (16,384 px a side, 100 MP, 200:1 — refused first at admission by `validate_edit_images_against`, since a tiny PNG can declare 60000²), reduced to 8 bits as Pillow does (16-bit PNG takes the high byte, `I;16` clamps), and EXIF-oriented and ICC-converted to sRGB, both DELIBERATE divergences from upstream's PIL `open`. Because the engine orients, every canvas authority reads `reference_image::oriented_dimensions` (Studio: `orientedImageDimensionsFromBase64`, the same EXIF reader), so a portrait phone photo sizes a portrait canvas. `OutputMetadata.has_alpha` is a fact about the stored FILE, `transparent_background` about the request. Still WebP goes through libwebp's simple API (`webp_still.rs`, no `ANIM` chunk) for EVERY image family — WebP was advertised but failed after the render before. LoRA on every tier is a forward-time bypass; a 2512 adapter is refused by name. Turbo tiers (`qwen-image-2.1-turbo:{bf16,int8-conv,q8}`) pin steps, guidance and sigmas from `manifest::qwen_image21_turbo_schedule`, the `wan_dmd_ladder` pattern. The vision tower and VAE encoder run F32 on every device, and the timestep is rounded to the latent dtype wherever no archived v0.32 bytes exist (the CUDA fast path always; Metal for everything but base-tier plain text-to-image) — both deliberate, see `.claude/rules/inference.md`. The Qwen Research licence (`QWEN_RESEARCH`) gates every file of every tier at download — only files a pull would FETCH, so re-pulling an installed tier is a no-op. A listed model whose profile lacks `capabilities.transparency` is an older server: the CLI and MCP probe `/api/models` before sending `transparent_background` and refuse with "update the server" (`require_remote_transparency_contract`). A non-empty `negative_prompt` to a recipe whose control is Hidden (every turbo/distilled tier) is a request WARNING, never a refusal (`negative_prompt_ignored_warning`).

- **A reference-conditioned request never auto-selects a GGUF Qwen3-VL language model.** `choose_qwen3_vl_variant(.., reference_conditioned)` keeps BF16 (on the card, else on the CPU; Metal stays on the unified pool). An explicit `MOLD_QWEN3_VARIANT` still wins, with a request warning. Evidence in `docs/qualification/qwen-image-2.1-image-conditioning.md`: Q8_0 measures 31.90 dB on the P8 turbo reference case, against a gate of 34.22 dB (upstream bf16 + 1 dB). Planner and engine read the same rule.
