# TUI invariants (mold-tui)

Moved verbatim from the root CLAUDE.md; loaded only when working under the paths above.

- **Don't break centered TUI image protocols.** `crates/mold-tui/src/ui/gallery.rs` uses a fixed-protocol thumbnail path, and `ui/preview.rs` uses the same centered fixed-protocol rule for transient SSE denoise previews. Do not revert either path to plain `StatefulImage` for Kitty/Sixel/iTerm2 — it reintroduces top-left padding instead of centered aspect fit. A new preview frame must invalidate only the transient geometry cache; start, completion, and error clear it so latent pixels never become final-output authority. Keep the regression tests passing. The Mold Studio spec now defines the TUI as the fifth shell (spec §05 "Terminal surface", gap G13, mockup `docs/design/mold-tui-proposed.html`) — future TUI restyling implements that, keeping this invariant and the key→action contract tests.
- **TUI Create form = essentials + Advanced accordion.** `crates/mold-tui/src/ui/create_form.rs` owns the row model (`CreateRow`, `AdvSection`, `visible_rows`) — the old `ParamField::visible_fields` is gone, Mode/Host rows never come back (routing = Machines `GenTarget`), and the inline Negative editor only renders while Advanced → Negative is expanded (`negative_visible()` is the focus/hit-test predicate). Video families add `Duration` to the essentials — plus `Predict duration` when the checkpoint advertises `supports_duration_prediction` — between Prompt strength and Seed. Advanced → Video shows Frames/FPS for video families plus checkpoint-aware LTX-2 Audio, latent-upscale, and guidance-override rows. Audio's tri-state `default` / `on` / `off` preserves an absent `enable_audio` until explicitly changed, enabling it selects MP4, and an advertised `supports_audio:false` hides it and clears stale authority. Spatial `native` / `1.5×` / `2×` and temporal `native` / `2×` preserve absent request fields until changed. STG scale/blocks, CFG rescale, modality scale, guidance skip, and wan's `SampleShift` flow-shift row (gated on `supports_flow_shift`) likewise stay absent from the request until touched; block input is validated before it can close, and leaving LTX-2 clears every stale video override. **Identity photo** sits between Source image and LoRA, gated on the checkpoint's advertised `/api/models[].supports_identity` (never the family or a compiled feature), and carries the Identity image / strength / start step rows. **File under** is the last section and has no capability gate — every model produces a print. Its Title/Tags/Collection rows are absent-until-touched popups validated through `mold_core::organization` _before_ they can close, and Title and Tags validate against each other because a titled print may pick up its own slug as a tag. That auto tag is composed by the same `mold_core::compose_client_tags` the CLI uses (the server never auto-tags) and is disclosed on the Tags row and in the section summary; the helper's one CLI-flavoured message (`--no-auto-tag`) is rewritten by `create_form::compose_filing_tags` to name Settings ▸ Library ▸ **Tag by title**, the TUI's own `generate.auto_tag_title` toggle, whose value the form snapshots into `GenerateParams.auto_tag_title` so the disclosure and the request cannot disagree. Filing is per-print intent, so `TuiSession` gains no slot and `model_prefs` no column, and only Reset to model defaults clears it; a forced-local save stamps it into `OutputMetadata` (where the DB seeds the row on insert) and uses `default_output_filename_titled`. Unlike web/desktop the TUI does not gate on `capabilities.gallery.organize` — it matches the CLI, whose target may be a local engine with no host at all, and lets the host drop-and-warn. Settings labels must stay shorter than `ui::settings::LABEL_WIDTH` or they render flush against their value. Accordion state persists at `tui.advanced_open`/`tui.advanced_section`; keep the `visible_rows`/summary/active-count contract tests and the `TIMELINE_HEIGHT >= TIMELINE_VISIBLE_ROWS + 2` const-assert green.
- **Runtime video-pipeline provenance is output authority.** `VideoData.pipeline` records the recipe that actually completed, including an implicit Auto choice. CLI and TUI client-side saves must apply that response value rather than infer it from `GenerateRequest.pipeline`, and TUI Library details render `OutputMetadata.pipeline` only when present so older and non-LTX prints remain valid.
