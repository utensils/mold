# Model removal / storage / identity contract (mold-core)

Moved verbatim from the root CLAUDE.md; loaded only when working under the paths above.

**Model-removal ownership invariant:** `mold_core::removal::model_owned_paths` is the single authority for "which on-disk paths does model X own", and every consumer — `build_ref_counts`, `plan_removal`'s unique/shared classification, the `mold rm` / `mold clean` orphan sweep's keep set, the TUI's removal view, and the server's `DELETE /api/models/:model` — derives from it. Ownership is read from the MANIFEST, never from the `[models]` config entry alone: a config entry is a `ModelPaths` projection with one field per component role, so it can name neither a role `ModelPaths` has no field for (`AudioVae`, `Processor`, `VideoScheduler`, `AudioScheduler`, `ModelConfig`, `TaskConfig`, the identity assets) nor the second file of a role a manifest declares twice (LTX-2.3 ships an x2 and an x1.5 `SpatialUpscaler`). Reading ownership off that projection is what let the sweep delete MiniMax H3's audio VAE and runtime support configs, and LTX-2.3's 1.09 GB x1.5 upscaler, out from under installed checkpoints. The union is manifest storage paths (those that exist) ∪ the config entry's own list ∪ derived artifacts no manifest walk can see (PuLID's converted tower and parser). Ref-counting keeps the "an incomplete owner does not hold shared bytes hostage" rule, and that completeness question is manifest-derived too (`configured_owner_is_complete`): a config entry that still lists every path it CAN name is not evidence, since the missing component may be one the projection has no field for — but the manifest half is asked only of models with manifest files on disk, so a config entry pinning every component elsewhere is still judged by its own list rather than disqualified. The SWEEP is deliberately laxer than either — `model_install_is_present` keeps a partially installed model's dependencies so `mold pull` can repair it, and `.sha256-verified` sidecars are kept with the files they attest. When ownership is uncertain, keep the file: a file wrongly kept costs disk, a file wrongly deleted breaks a running install. The sweep prints every path it actually unlinks — the shared file plus, for an hf-cache-backed orphan, its blob and each snapshot symlink — never only a count. `execute_removal` deletes each removed file's `.sha256-verified` marker with it (a marker attests to ONE file and `manifest_files_exist` accepts its presence as proof of a complete install, so a stranded one would vouch for whatever is written under that name next) and walks the emptied model directory up to — never past — the models dir.

**Model storage permissions invariant:** model weights, configs, support files, model roots, and runtime staging roots must never be rejected because of Unix owner/group identity or group/other write-mode bits. Shared storage and collaborative umasks such as `0664` are valid. Verify newly acquired bytes against pins; trust complete installed files at runtime using regular-file and symlink checks, canonical containment, and descriptor identity fencing; loaders that stage into a shared parent must construct from retained process descriptors rather than a replaceable pathname. Owner-only permission requirements remain appropriate for credentials, authorization records, and retained private evidence, never for runnable model artifacts.

**Integrity belongs to acquisition and explicit verification.** `download::installed_artifact_identity` and `installed_file_is_complete` never read model bodies. Queueing, loading, repair no-ops and switching cannot call the hashing fallback. Missing private receipts resolve to tagged local installation identities, frozen per file identity/process; do not record expected manifest pins as observed SHA values. `mold info MODEL --verify` still reads current bytes. Same-size corruption is no longer guaranteed to be caught at runtime admission.
