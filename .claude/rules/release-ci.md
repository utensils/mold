# CI gates, release-plz, AUR

Moved verbatim from the root CLAUDE.md; loaded only when working under the paths above.

**CI gates** (`.github/workflows/ci.yml`): PRs keep the required `rust` status, which since 2026-09-10 is ONE build — `scripts/ci/affected-packages.py` maps the diff to the workspace packages it can reach (dependents and cross-crate `include_str!` pins included; `Cargo.lock`, `.cargo/`, workflows, `build.rs`, `vendor/`, `tests/fixtures/` widen it to the workspace) plus the optional-feature union for those packages, and that selection is linted once and run once through `cargo nextest run --profile pr` (`.config/nextest.toml`: the six default-feature assertions and the 116-test heavy long tail are excluded; every clause is an exact name so a renamed test rejoins). A push to `main` runs two Rust lanes in parallel: `rust` keeps the per-feature H3 arms (`h3-private-uat` alone is the record runtime), the private developer bins, and the union clippy and union nextest builds — the latter is what warms the dependency cache PRs restore, so never drop it — while `rust-default` runs the default-feature clippy and the complete workspace suite (`cargo nextest run --profile main --workspace`, every test, one retry so a lone flake reports FLAKY instead of red). `rust-default` restores `workspace-default` with `save-if: false`; `rust` is that key's only writer, because two writers race and a PR could restore a cache with no union artifacts. Both jobs set `CARGO_PROFILE_DEV_DEBUG=line-tables-only`, and neither uses sccache (its GHA backend never stored anything here and its probe flipped `RUSTC_WRAPPER`, which rust-cache hashes into the key). The MSRV toolchain check lives in `.github/workflows/msrv.yml`: weekly, on demand, and on manifest or lockfile changes to `main`, never on the merge path. Beyond `rust`, PRs keep fmt, relevant Metal forced-local checks, `web`, `docs`, desktop/iOS compilation, and path-gated release contracts. Shipped CUDA targets compile in release workflows instead of a duplicate 40+ minute forced-local CI job — but a `cargo check` of the CUDA cfg ARM is not that job and is on the PR route as `cuda-typecheck` ("CUDA forced-local typecheck"). `#[cfg(any(feature = "cuda", feature = "metal"))]` guards the mold-cli call sites into `mold_server::execution_plan`; `metal-check` compiles one of those two arms on macOS and `cuda-typecheck` compiles the other on `ubuntu-latest`, because a default-feature PR build type-checks NEITHER and a mold-server signature change otherwise lands green while every shipping CUDA artifact fails with E0061. It compiles the SHIPPING feature set minus `cudnn` (`h3-cuda,preview,discord,expand,tui,webp,mp4,metrics,mdns,pulid,mesh-texture,mesh-matting,mesh-delight`) — a `cuda`-only check stayed green while a change broke an initializer inside the private H3 arm, which guards 300+ cfg sites in mold-server and mold-cli; `cudnn` is omitted because cudarc needs the cuDNN headers at build time and mold's own crates carry no `cudnn` cfg arm. It runs on the `cuda_typecheck` paths filter (`crates/mold-cli`, `crates/mold-server`, `crates/mold-inference`, the root manifests, `ci.yml`), installs nvcc through `Jimver/cuda-toolkit` because candle-kernels' build script emits PTX before any Rust in the CUDA graph can be checked, and RESTORES `workspace-default` with `save-if: false` — it must never own a rust-cache key while the Actions cache store sits at its 10 GB ceiling. `scripts/tests/ci-routing-contract.sh` pins all of that, including that the job is not the retired forced-local build. Codecov coverage and the live external-catalog monitor remain on `main` without blocking PRs. **The FlashAttention compile check does NOT** — `flash-attn-check` ("CUDA feature checks and H3 server tests") was commented out in 48dbb266 ("ci: disable H3 CUDA server job", merged with release PR #1607) to stop the H3 CUDA server suite, and the `--features flash-attn` compile went with it as collateral. Nothing in CI has compiled that feature since; the dead block has now been deleted rather than left as a false promise, and `scripts/tests/ci-routing-contract.sh` asserts `flash-attn-check:` is absent from `ci.yml` in ANY form so it cannot return as a comment. That contract reads only ACTIVE YAML (lines whose first non-space character is `#` are blanked before any assertion), because for months it reported a CUDA compile gate purely from the text inside that commented block. Reviving the flash gate is a deliberate decision, not a cleanup: the job owned a `workspace-cuda-flash-sm89` rust-cache key plus an `actions/cache` for `~/.cudaforge` and the kernel build directory, and the Actions cache store is at its 10 GB ceiling. `./scripts/ci-local.sh gpu` is the developer-side gate meanwhile. Repository-owned release-plz PRs take an allowlisted fast path through locked-manifest and release-contract validation, bridged into the protected `rust` status. Required jobs fail closed if path classification fails. All triggered gates must pass.

- **Releases are automated by release-plz** (`release-plz.toml`, `.github/workflows/release-plz.yml`). Every push to `main` maintains a release PR: release-plz bumps the shared `[workspace.package]` version (conventional commits decide the bump; `feat:` ⇒ minor on 0.x), then a scripted bot commit (`scripts/release/sync-release-pr.sh`) assembles every `changelog.d/*.md` fragment into `CHANGELOG.md` `[Unreleased]` (newest first, by the commit that added it), deletes the fragments, promotes `[Unreleased]` to the new version, syncs the desktop cargo root's version, and copies the promoted notes into the PR body — never bump versions or promote the changelog by hand. release-plz itself never touches `CHANGELOG.md` (`changelog_update = false`); the CI trusted-release-PR file-scope check allows exactly `D changelog.d/*.md` beyond the modified version files, and the release tag job refuses to tag while an unassembled fragment is still on `main` (a fragment merged between the release PR's last sync and its merge would otherwise ship its code now and its note next version). After that PR merges, `release-plz-release` waits for the exact main SHA's published notarized macOS Nightly and `VALID` TestFlight build, then pushes the `vX.Y.Z` tag that fans out to release.yml and FlakeHub. Tagged publication is priority-staged: signed/notarized Apple artifacts and the stable updater manifest publish first, native Linux archives and AUR follow their CUDA builds, and the lower-priority container matrix attaches exact digest/provenance metadata last. Best-effort Nix distribution builds run independently and populate Cachix; they never block native or Apple publication. Rolling `latest*` image aliases are refreshed by the scheduled container run and by `v*` tags, never by plain `main` pushes (`release.yml`). Stable `<version>*` container aliases are create-once and verified, but automatic Lambda/RunPod/desktop provisioning must consume the release's exact `mold-container-digests.json` `@sha256` reference and fail closed until it is available and consistent. Both workflow jobs authenticate as the `release-plz-mold` GitHub App (`RELEASE_PLZ_APP_ID`/`RELEASE_PLZ_APP_PRIVATE_KEY`) so CI runs on the release PR and the tag triggers workflows; the follow-up commit must retain that bot identity or release-plz will replace the PR to preserve human-authored history. Merging the release PR ships the release — treat it as outward-facing. Gotcha: release-plz refuses to run if any tracked file is also gitignored (`git ls-files -ci --exclude-standard` must stay empty).
- **crates.io distribution is retired.** The backend uses exact Git revisions that registry dependencies cannot preserve. Do not restore the registry publish job or recommend registry installation. GitHub releases, Nix/FlakeHub, Docker, AUR, and source builds remain supported; existing crates.io versions are historical. `scripts/tests/crates-publish-contract.sh` guards this policy in CI and local release contracts. release-plz manages workspace versions and tags with `publish = false`. The PR workflow supplies `--registry-manifest-path` from the latest reachable stable `vX.Y.Z` worktree; disabling publication alone still compares against stale registry versions and silently prevents the next release PR. Keep the shared workspace tag pattern for all lockstep crates. Do not replace the explicit baseline with `git_only` until upstream stops packaging the tagged workspace: release-plz 0.3.162 calls `cargo package --workspace`, which rejects our Git-only Candle dependencies.
- **AUR PKGBUILDs auto-publish on `v*` tags.** `packaging/aur/{mold-ai-bin, mold-ai}/PKGBUILD` are the source of truth; CI rewrites their `pkgver` + `sha256sums` in the `publish-aur` job and pushes to the AUR git repos. The existing `-bin` package stays on the `cuda-sm89` release tarball. RTX 3090/A40, B200/B300, and RTX 50-series users build the source PKGBUILD with `CUDA_COMPUTE_CAP=86`, `100`, or `120`; do not publish an sm100 binary AUR package before real B200 qualification. GH200, GB200, and GB300 Grace systems remain unsupported until linux/arm64 artifacts exist. `mold-ai-git` is hand-pushed when the build recipe changes. AUR packages declare `conflicts=('mold')` because they collide with the rui314 linker at `/usr/bin/mold`. The in-tree `mold update` correctly bows out on `/usr/bin/mold` and `/usr/sbin/mold` Linux installs.

Changelog-only release repair pushes must trigger both Desktop and iOS: the tag gate requires Apple candidate delivery at the exact repaired main SHA, even when the version and application source are unchanged. `scripts/tests/ci-routing-contract.sh` pins these push paths.

- **`scripts/test-h3-cuda-server.sh` no longer runs in CI at all.** It used to ride the CUDA toolkit job for PRs touching the H3/server dependency paths, running the complete hermetic `h3-cuda` server library suite with a thirty-minute test timeout against the driver link stub and no physical GPU; 48dbb266 switched that job off and nothing replaced it. The `h3_cuda_server` paths filter in `ci.yml` is now consumed by no job. Live CUDA qualification must still run on hardware. If the suite is revived, the wrapper clears all `MOLD_*` overrides and isolates XDG config; do not replace the full suite with a name filter.

The H3 CUDA server wrapper defaults `RUST_TEST_THREADS` to 8 so large hosts do not launch hundreds of timing-sensitive owner tests at once; an explicit test-thread setting remains available for diagnosis.

Fake-engine worker fixtures opt into `GpuWorker::mock_device_memory` for post-drop samples and skip real H3 context adoption; legacy queue fixtures use the matching `AppState::mock_device_memory` probe. This test-only boundary must stay explicit: a missing GPU or failed production probe must never select a fake sample. Hardware fixtures leave it `None`; error and capacity-refusal tests inject typed failures through the same allocation boundary.
