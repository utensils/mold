# Video clips, scripted sequences and durable chain jobs

Moved from the root CLAUDE.md; loaded only when working under the paths above.

Across browser, Tauri desktop/mobile and native macOS/iOS, enter one prompt and choose **Duration**. Keep the selected recipe's normal short duration by default; longer durations use bounded clips with the recipe's continuation or blend. Show the single-generation duration and planned clip count. **Define scenes** (browser/Tauri) or the **Longer video** toggle (native macOS/iOS, whose one shared `NativeLengthControl` is a Length slider capped at one generation, in exact seconds for Duration) is optional; each scene is capped at the always-one-clip length from the video-job plan. Library **Extend video** accepts a new prompt and added duration, publishing the complete original plus extension as a new MP4 while retaining the original. Keep ordinary generation and Reuse settings available. Legacy scripted sequence continuation remains a separate linked-output API.

Keep the existing output switch and route. Do not restore the old timeline, `Simple | Scenes` strip, or second output mode. Web, Tauri desktop/mobile, and native macOS/iOS share the durable API contracts. Discord exposes a compact `/video` group alongside ordinary `/generate`.

- `mold run --script shot.toml` — canonical TOML, schema `mold.chain.v1`. Per-stage `prompt` / `frames` / `transition`.
- `mold chain validate shot.toml` or `mold run --script ... --dry-run` to inspect without submitting. `mold chain limits MODEL --json --host HOST` reads live bounds over the paired client; listing is `mold jobs list`.
- One-prompt duration: remote `mold run MODEL "prompt" --duration 45 --dry-run --host HOST` fully validates the owner-bound `/api/video-jobs` plan; omit `--dry-run` to create its durable parent. Require affirmative `video_jobs` support. Each child uses the server recipe’s normal short window, except MiniMax H3, whose children use its full single-generation ceiling (345 frames, 14.375 s; upstream renders 4–15 s per pass), so a 14 s request is ONE clip; the parent trims clip-grid padding to the requested length on the output FPS clock. `mold run MODEL --scenes FILE.toml` sends ordered `scenes` (one `[[scene]]` with `seconds` + `prompt` each, `deny_unknown_fields`; the length is their sum and a contradicting `--duration` is refused). A scene (or single prompt) spanning more than one clip is rendered again per clip and its action repeats: admission adds a plan warning naming the always-one-clip limit `(single_clip_max_frames - overlap_frames) / fps` floored to 0.1 s, and another for a scene shorter than the minimum generation. Admission validates EVERY scene's prompt, not only the first. New H3 FL2VA parents seal `continuation_instruction` in the manifest and each carried clip's prompt opens with upstream's alignment line (`base-en.txt` §2.1: I2VA, or FL2VA when the final clip keeps a closing frame), replacing any authored one; parents sealed without the flag resume with byte-identical children. `VideoJob.progress_phase` (`waiting`/`rendering`/`joining`, additive, derived per read from scheduler/registry state, never persisted) says what a `running` parent is really doing, and `docs/contracts/video-job-rows.json` is the one row wording every surface renders. H3 FL2VA carries motion; Ref2VA, text-only Wan and legacy LTX use independent blended clips. Authored `--frames`/scripts keep their existing chain limits. Forced-local Duration remains one bounded H3 generation. Paired-host inspection uses authenticated CLI commands, never raw curl at a proxy URL.
- Sugar: `mold run <model> --prompt "..." --prompt "..." --frames-per-clip 97` (uniform smooth only).
- Transitions: `smooth` (default, model-specific continuation), `cut` (fresh clip), `fade` (cut + RGB crossfade). LTX-2 carries latent motion; image-conditioned Wan and H3 FL2VA carry the final RGB frame (one-frame trim). Text-only Wan, legacy LTX-Video and H3 Ref2VA concatenate independent clips with zero tail.
- H3 sequences require the server route: each stage receives fresh preparation/admission and a single-use owned attempt. Never execute them through the generic engine cache; forced-local H3 chains remain refused.
- Typed per-stage media: `generation_references` uses the ordinary generation reference schema; `keyframes` uses typed boundary keyframes. TOML `first_frame_path` / `last_frame_path` resolve relative to the script into frame `0` / `frames-1`, and cannot mix with keyframes or source images. FL2VA accepts endpoints; Ref2VA accepts references and rejects endpoints. An incoming smooth carry must not silently replace an authored first endpoint. All media must survive seal/hydrate, resume, retake and amend; changes invalidate the cached prefix.
- Authored input bytes are encrypted separately. `authored_media_sha256` is recomputed by the server before scrubbing; it binds source/keyframe/reference contents so media-only amendments cannot replace a prior manifest's authority before commit. Hydrate the canonical stored request before retake prompt/seed overlays. `mold jobs show --script` explicitly fetches `GET /api/chain-jobs/{id}?include_source_media=true` for portable media-bearing TOML; ordinary detail/SSE remain scrubbed and the export is private/no-store. This content hash never authorizes caller-provided descriptors or paths.
- Full-range seeds survive TOML export: seeds/offsets above `i64::MAX` serialize as decimal strings, and the private TOML wire reader accepts strings or integers. Keep the JSON/API field types unchanged.
- Per-stage source images: `source_image_path` (relative to script file) or `source_image_b64`. Resolved by `mold_core::chain_toml::read_script_resolving_paths`.
- **An auto-chained one-shot is distinct from an authored multi-clip video.** `ChainRequest.ephemeral` (additive, absent means authored) is the distinction, set on the ONE creation path: `mold run --frames 200`, or a length slider past the checkpoint's clip size, renders a long video as a chain because the model cannot do it in one pass, so its job is absent from authored `GET /api/chain-jobs` listings and emits no `chain_job_queued`, while `/api/activity` still exposes the live job on every client. Ephemeral means hidden from sequence history and swept only after settlement; it does **not** mean disposable while active. Graceful shutdown parks it as `paused`, preserves its manifest, source media, completed clips, and tail cache, and allows explicit resume after restart. Its final print carries `chain_job_id: None`. It DOES publish its print with full per-clip provenance. Stage seeds are recorded either way — they describe how the pixels were made, not who authored the split.
- **A one-shot may never silently become a context-free chain.** `mold_core::chain::text_only_auto_chain_refusal` is the server authority: a wan tier whose `source_image` contract is `Unsupported`, or any legacy `ltx-video` tier, hands nothing across a clip boundary, so identical prompt-and-seed stages repeat. Text-only Wan is refused above its clip size at the CLI, in every app, and at `POST /api/chain-jobs`. Legacy LTX-Video takes the other honest route: the CLI and the apps keep it as ONE denoise up to its 257-frame engine ceiling, while server admission rejects a manually submitted `ephemeral` multi-stage request. The Wan and LTX-Video surface-parity fixtures pin the family-specific sentences. SCRIPTED sequences still compose independent clips because there that is what the author asked for.
- **Random seed authority:** an omitted chain seed is materialized once by `ChainRequest::materialize_seed` before dispatch or durable manifest creation; explicit `0` is fixed. The database request JSON must match the manifest’s resolved request, and stage seeds derive from that persisted base and authored offsets. Resume/retake of existing manifests keeps their recorded authority; never reroll at a stage boundary.
- **A remote sequence is a DURABLE CHAIN JOB.** `POST /api/chain-jobs` creates one and `GET /api/chain-jobs/{id}/events` streams its stage progress; `mold run --script` takes that route and hydrates the stitched print from the host's gallery. The synchronous `POST /api/generate/chain` and SSE `POST /api/generate/chain/stream` shims are DELETED — they ran a chain as a hidden ephemeral job and deleted its artifacts after answering, so a dropped connection lost work that could not be resumed, retaken, or reattached. `POST /api/generate/chain/validate` survives and is the only thing left in `routes_chain.rs`, which is read-only planning. A `--script` run therefore leaves a job `mold jobs list` can find, and the CLI does not receive the host-side thumbnail or GIF preview inline. The whole endpoint family — create, events, resume, retake, amend, cancel, delete, gc, stage media, and `/api/capabilities/chain-limits` — stays supported; the apps use durable authored jobs for Add clip and retain the separate ephemeral one-shot path.
- **Long sequences use linked bounded parts.** Sixteen stages and the advertised frame limits apply to each part, never the lifetime of a sequence. `continue_from` selects a predecessor's latest completed finalize take; `mold run --script next.toml --continue-from JOB_ID` resolves it. There is no successor-part count or chain-follow wall-clock deadline. Each part publishes its own MP4 and owns a bounded snapshot of its incoming tail, preserving the predecessor's frozen artifacts, canvas, fps, tail contract and audio setting. Sampling controls and prompts may change. Deleting predecessor caches after successor acceptance must not break dispatch; gallery provenance pins retain the incoming snapshot after successor GC. A positive incoming tail forbids an authored first endpoint; independent zero-tail models retain ordinary authored-input behavior. Older servers without an affirmative `linked_parts.supported` capability must be refused before submission. Continued job manifests use `mold.chainjob.v2` so older binaries refuse them during rollback; ordinary manifests remain v1. Continued links are immutable through amendment.
- **Blind-test the canonical chain skill.** Render the actual CLI skill bundle and give a fresh Luna agent only that bundle, the task, host and output location. Use the lowest available reasoning setting. Exercise real CLI validation, submission and published-output download; record friction, improve the canonical skill, then repeat with a fresh agent. Keep scripts, receipts and videos under the tested server's `MOLD_HOME`, and verify the final print is visible in its active Library.
- **Bound admission before allocation.** A part accepts at most 32 MiB of aggregate decoded inline authored media and 64 retained members, including incoming-tail members. Validate auto-expanded copies before constructing them. Chain create/validate/preview/amend JSON limits account for base64 expansion; default Axum body limits must not contradict the advertised media budget.
- **Use Settings and Extend are separate actions.** New `metadata.video_job.authoring` restores the original requested added duration/scenes, literal prompt and exact seed into a fresh editable movie, never an implicit prefix. Extended-print reuse explains that the original video is not attached. Older authored `metadata.chain` restores all recorded stages with their exact input roles, effective seeds, LoRA stacks and joins; never flatten or narrow to the first prompt. Explicit legacy `output_mode: one-shot` restores one prompt plus honestly labelled saved-length duration only when prompts, controls and input topology prove a uniform automatic split (uniform or base-XOR-index effective seeds). Refuse unrepresentable explicit one-shots before mutation. Disclose missing historical per-stage controls. Inspect the exact clicked authenticated physical copy and installation before restoring inputs; private clip media never goes in preference journals.

## Interactive authoring invariants

- Derive frame grids, carry contracts and bounds from the selected server. Validate before publishing and display its delivered duration. Additive `chain-limits.authoring` advertises model-normalized tail, grid and `source_fit_supported`; never silently discard source-fitting provenance on an older host.
- Freeze host, credentials, persistent installation identity and draft revision across every asynchronous read and write. Persist a known operation UUID before POST; reconcile ambiguous replies against that UUID without replaying inference. Failed/paused jobs remain recoverable.
- Continue only the exact original owner and latest published filename/take, with affirmative linked-parts support. Freeze model, canvas, fps, audio and tail. Hydrate retained typed references explicitly and visibly; repeat references across clips, map first endpoint to clip zero and final endpoint to the last clip. Bound copies before allocation. Persist scalar drafts and locators, never inline media or credentials.
- Queue progress represents the parent and its clip progress. Cancel during admission must reconcile the accepted operation. Announce Library success only after a published filename exists.
- UAT renders target Plato and its active `/storage/mold` Library. Keep receipts under `/storage/mold/uat/`; verify publication, frames, fps and audio. Native Simulator proof is distinct from physical-device proof.

## Authoring contracts and recovery

`chain-limits.authoring` additively reports the selected checkpoint's normalized tail, carry mode, frame minimum/grid and `source_fit_supported`. Use the same concrete source-image contract as admission, including installed Wan headers and H3 task identity. Preserve `source_fit` through request, script and stitched metadata; fitted pixels are already prepared.

Materialize an omitted base seed before sealing the request's authored-media revision. Legacy jobs sealed with an omitted seed may recover only through the exact alternate digest obtained by replacing the base seed with `None`; retain every other field, authored byte hash and predecessor link, then perform ordinary authenticated hydration. Gallery handoff uses the same lookup. Never ignore seeds globally or scan for a similar request.

H3's durable singleton stage is internal work beneath its chain parent. Its trusted generation→chain/stage association is committed in SQLite in the same transaction as batch admission, including the exact video-parent identity when present. Public request fields, titles, tags and deterministic client IDs never establish ownership. Idempotent reattachment requires the stored association to match; never guess or backfill unmapped historical work. The association survives queue settlement with its batch receipt. Feeder claim, bounded runtime-window publication and the final token-fenced pre-GPU dispatch all require the chain to be Running and its captured video parent to be Running without cancellation intent; missing owners refuse. A private bounded `active-stage-child.json` remains Activity presentation metadata, not execution authority.

Before reattaching or cancelling an existing H3 stage batch, verify the exact canonical request through durable admission's authenticated receipt; its public client ID alone is insufficient. Stream and fsync its exact delivered video into the parent's private artifacts before moving the intermediate print to recoverable Trash under the gallery publication writer. Recovery reads live or Trash bytes only when that retained artifact is missing. A Trash failure leaves the live print and does not fail generation; a retention failure must never discard the only copy. That stage publication is announced as `gallery_added` with `internal: true` (`queue::is_sequence_stage_print`, read from `chain_stage_generations` by the print's `job_id`), so clients that announce or count arrivals (the Mac's `LandedPrints` notifications, desktop's landed-prints badge) skip it like an import. It is still an ordinary gallery event for Library sync, and its Trash event follows.

**Restart is a separate new attempt.** Failed/interrupted sequence parents remain in `/api/activity` with honest terminal phases and no Cancel action so Queue can recover them after reload. `GET /api/chain-jobs/{id}/restart-options` reports per-parent Restart/Send support and refusal reasons without hydrating media. `POST .../restart-export` requires the captured `source_instance_id`, `source_revision` and `destination_instance_id`, authenticates exact retained authored bytes under the job lock, and never changes the failed/paused source. Clients require affirmative `capabilities.queue.chain_restart` on the destination; older servers silently ignore the owner header. Target ordinary chain creation uses a new persisted operation UUID and optional `x-mold-destination-instance` fence; revalidation captures today's target recipe. It must never bypass frozen authority checks on Resume. Linked predecessors remain explicitly unavailable until their conditioning can be preserved. Same-machine Restart retains local adapters for ordinary target validation; Send refuses machine-local adapters. `request_json` in the export is wire-ready protected JSON: browser clients forward it unchanged to preserve full-range seeds and literal prompt text, without storing private media. `mold jobs restart ID [--to HOST] [--operation-id UUID]` prints the identity before admission; reuse it after an uncertain response.

Internal Duration child-chain UUIDs are reserved atomically with the exact parent part ledger, before child creation. Their scalar ownership survives parent deletion. Public creation/Resume/Retake/Amend/Cancel/Delete/Restart and ordinary stage controls refuse these IDs; clients act on the video parent. The actor captures the part while holding the same child mutation lock public creation uses. Generic execution rechecks durable parent intent after installing its cancellation token, closing Stop-before-registration without putting DB reads in denoise progress callbacks. Public chain GC skips owned children; settled parent cleanup releases exact stage queue inputs before removing private artifacts. Empty Queue and Resume Paused refuse when they would change owned clips, with a final transactional guard for an admission arriving in flight. Ordinary-only bulk operations keep their existing behavior.

## Durable duration parents

`/api/video-jobs` owns a single prompt or optional scenes and an exact requested duration. It reuses one bounded, private chain child per clip; queued parents own no decoded tails or assembly writer. The active writer count is limited to available GPU workers. A source prefix and authored inputs are sealed once under the captured database home.

Claim each child in the parent ledger before creation under the shared child mutation lock. Persisted child ownership must gate ordinary H3 dispatch and public controls, including after parent deletion. A private segment's MP4 and receipt hashes become immutable in the same parent checkpoint; only then may a settled child's raw caches and encrypted inputs be removed. Rebuild from authenticated segments after interruption, never by rerendering completed clips or rewriting an ever-growing prefix per clip. Publish one final MP4 and hand off encrypted authored inputs and PCM/provenance artifacts to its exact Gallery archive authority before marking Completed.

The literal video protocol requires installation-fenced reads/mutations and fresh full validation before CREATE; planning-only validation has no admission proof. Partial input claims remain private until explicit Stop, and only fully claimed pending admissions may reconcile into public jobs. MP4-disabled builds expose no duration admission routes.

Browser/Tauri **Start again…** is a new attempt, distinct from exact Resume. Read restart-options, capture source revision and destination installation, require affirmative destination `queue.chain_restart` before export, export for that destination, and POST its opaque wire-ready request_json unchanged. Never JSON-parse/re-encode full-range seeds. Persist the operation and both owners before admission; reconcile ambiguous replies by that ID and cancel only that destination operation. The original is never automatically cancelled, moved or removed. Failed/interrupted Activity parents remain visible as recovery work, never as GPU work still rendering.

Recovery deletion uses only affirmative `restart-options.discard.supported` and `POST /api/chain-jobs/:id/discard` with captured `source_instance_id` and `source_revision`, under the job lock, Failed/Interrupted only. Never implement GET-then-legacy-DELETE. Missing manifests refuse restart but still permit explicitly confirmed recovery-data deletion; saved Gallery outputs remain untouched. Safe new-attempt cancellation requires affirmative `queue.chain_restart_controls` and the captured `x-mold-destination-instance` on the known operation cancel route; the server rejects a provided mismatch before recording any tombstone. Persist cancellation intent and replay only that exact operation during explicit recovery.

Accepted **Stop** pauses a duration parent after its exact child execution authority has settled and owned H3 queue leases have retired. Preserve completed clips and sealed inputs; offer explicit **Resume**, **Start again/Send**, and **Discard**, without automatically resuming. Paused parents do not offer another Stop. Unknown or private pre-admission Stop remains an irreversible operation tombstone. Historical Cancelled parents remain discoverable and support a new attempt; do not rewrite them or offer exact Resume.

Published Duration metadata includes `video_job.authoring`: exact requested `duration_ms` (added time for Extend), optional ordered literal `scenes`, decimal-string `seed`, and `boundary_frames` from the qualified single-clip template. Optional `input_frames` preserves the original authored endpoint locator when it differs from that template; use `input_frames ?? boundary_frames` to match retained closing-frame metadata, never the published total frame count. **Use settings** creates a fresh editable generation draft. For an extended print, disclose that the original video is not attached. Authenticated Gallery media roles remain the only authority for authored images/endpoints/references after parent Discard. Missing authoring on older prints does not authorize guessing scenes or restoring a joined prompt. Authoring JSON is limited to 1 MiB at admission, with an explicit refusal and no truncation or time limit.

Admission seals the original authored frame count and endpoint locators unchanged. Validate a normalized single-clip clone and remap endpoint positions only when building each bounded runtime child; changing the sealed locator would lose reusable authoring provenance.

Generation base seeds and authored-chain base/offset seeds accept exact unsigned decimal strings as well as existing JSON integers. Canonical serialization remains numeric so request scopes and existing clients retain the same identity.

## Extension audio authority

An accepted duration parent freezes audio decoded from the exact retained input MP4 into authenticated, parent-owned PCM at admission. Resume reads this sealed PCM, never a mutable original Library sidecar. Deleting the original print or its native pre-AAC audio bundle cannot change the extension. Restart/Send carries the exact MP4 and seals its audible audio again for the new attempt. New generated clips retain native PCM until the final encoding; silent suffixes receive exact frame-clock silence. Historical parents with audible MP4 sources but no sealed PCM fail closed and require a new attempt. Decode, hashing and assembly use disk-backed bounded buffers.
