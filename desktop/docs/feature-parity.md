# mold — User-Facing Feature Inventory (native-app parity)

Sources of truth: CLI clap defs (`crates/mold-cli/src/main.rs`), core wire types (`crates/mold-core/src/types.rs`), shared desktop/mobile capability and request logic (`desktop/src/lib/`), desktop UI (`desktop/src/`), iPhone UI (`desktop/src/mobile/`), native iOS bridges (`apps/mobile/src-tauri/`), server routes (`crates/mold-server/src/routes.rs`), catalog (`crates/mold-catalog/`), config (`crates/mold-core/src/config.rs`, `crates/mold-db/src/settings.rs`), chain (`crates/mold-core/src/chain.rs`, `chain_toml.rs`), Discord (`crates/mold-discord/src/commands/`), and TUI (`crates/mold-tui/src/`).

Frontend parity is maintained through the repo-root Bun workspace: `studio/`
owns browser-safe current-contract transport, Pinia state, and shared domain
logic; `ui/` owns tokens and low-level primitives; `web/` and `desktop/` own
surface navigation and platform adapters. Web intentionally requires current
server and storage schemas, while desktop and iPhone retain native
compatibility normalization. Browser routes are `/create`, `/library`,
`/models`, `/machines`, `/machines/:id` (host detail), and `/settings`; retired
routes are not redirected and every unmatched URL renders Page Not Found.

## 1. Core generation parameters (the shared `GenerateRequest`)

canonical form/request builder and prune it through the same family capability
map. Defaults come from the model's `ModelConfig` unless overridden.

TUI pipeline parity is deliberately bounded to recipes its existing Create inputs can run: Auto (field absent), `one-stage`, `two-stage`, `two-stage-hq`, and `distilled`. The row selects MP4, follows the shared recipe-specific CFG/negative-prompt contract, and participates in summary, active-count, reset, and incompatible-family pruning. `ic-lora`, `keyframe`, `a2-vid`, `retake`, `lip-dub`, and audio-only `t2a` remain omitted until TUI can author and handle their required conditioning media or artifact type end to end.

Desktop parity: `upscale_model` is surfaced by the always-visible icon-led "Upscale" select in Advanced on desktop and web (image families only; explicit Off option; lists every known upscaler from `/api/models`, downloads on first use on the selected generation host, including multi-GPU remotes), and the gallery's right-click **Upscale** action drives `POST /api/upscale` directly, saving the result to the local gallery (`/api/upscale` does not persist server-side). `source_image` / `mask_image` are surfaced by `SourceImageWell.vue` — a **Choose from gallery…** picker (`ImagePickerModal.vue` — upload, or the same merged multi-host gallery as the Gallery's All view: every connected host's still images deduped by the gallery store, tiles labeled with their host when more than one source exists, bytes fetched from the print's own origin host) plus an **Edit mask…** brush/erase canvas (`MaskEditorModal.vue`, invert / clear / undo-redo cap 20 → white-on-transparent PNG). A **Source fit** selector (the policy itself is shared: `@studio/lib/sourceFit.ts`) picks how a source that doesn't match the requested width×height maps onto the canvas — Pad repaint (default; generated white pad-band mask → repaint), Crop fill, Pad fit, Lanczos resize, or Upscale then fit (`POST /api/upscale/stream` preprocessing seeded from the post-generate upscaler pick). Fitting runs client-side on submit (`desktop/src/lib/sourceFitPreprocess.ts` over the shared `@studio/lib/sourceFitCanvas.ts`); an existing inpaint mask is refit through the same transform, and the generation host is resolved BEFORE preprocessing so a cache miss for the pre-fit upscale (and its model auto-pull) lands on the host the job routes to. Desktop, web, and iPhone each keep a per-composer single-entry cache: the deterministic upscale result survives target-size and route changes, while the fitted source/mask is keyed by source, mask, policy, and target size; in-flight Batch siblings share the same pass and failed entries remain retryable. The LTX-2 advanced fields (`pipeline`, `spatial_upscale`, `temporal_upscale`, `retake_range`, `source_video`, `keyframes`, `guidance_overrides`, and `audio_file` for the a2-vid pipeline) render directly in the always-open Video section (ltx2 family only, gated by `capabilities.supportsAdvancedVideo`; kebab-case enum values, nulls omitted, pruned on family change). The gallery image picker (`ImagePickerModal.vue`) filters its grid to PNG/JPEG, the only still formats the generate endpoints accept. Keyframe frame indices follow the web SPA (0-based, +24 suggestion) — not the 8n+1 total-frame-count constraint. A **Camera motion** select in the video section (ltx2 only) surfaces the host-compatible camera-control LoRAs plus a custom `.safetensors` path. Built-ins are reported by `/api/capabilities/ltx2-camera-controls`, remain selectable before installation, and download on first use on the exact generation host. One-shot requests append `{ path: "camera-control:<preset>" | <raw path>, scale: 1.0 }` to `loras[]`; sequence Advanced stores the choice per clip and writes the same entry to that stage's `loras[]`, so different clips may use different moves. Hosts with no compatible built-ins (currently LTX-2.3) keep the custom-path escape hatch instead of rendering disabled options. Wan's own advanced group is a **Sampler recipe** section (web, desktop, and the iPhone Advanced sheet, gated by `capabilities.wanRecipe`): a **Sample solver** picker that writes the shared `scheduler` field — narrowed to wan's `uni-pc` / `euler` / `dpm-pp`, which replaces rather than joins the generic Scheduler section — plus **Flow shift** (`sample_shift`) for every wan checkpoint and **High/Low-noise distill** (`distill_strength_high` / `distill_strength_low`) only on the A14B tiers that ship a Lightning adapter. Every control is absent-until-touched (`studio/lib/wanRecipe.ts`), so an empty box keeps the resolved tier's own value; out-of-band entries are named inline and block submit rather than being dropped, and the fields are pruned off-family and off-tier because the server rejects them there.

Desktop parity: `edit_images` is surfaced by `SourceImageWell.vue`'s qwen-edit branch — when `capabilities.sourceImageMode === "qwen-edit"` the single source well is replaced by a reorderable picture strip (index 0 = **Target**, rest = **References**; role/title labels and reorder semantics ported from the web Composer via `lib/editAttachments.ts`), fed by the multi-select `ImagePickerModal.vue` with drag or ‹ › reordering and per-tile remove. The ordered strip ships verbatim as `edit_images` (`form.imageAttachments` → `buildRequest`), batch is locked to 1, and `pruneRequestForFamily` now KEEPS `edit_images` for qwen-edit (it used to strip the image entirely — even single-image edits were broken) while stripping it from every other family and never letting `source_image`/`strength` through for qwen-edit. Switching single→qwen-edit seeds the strip with the attached source as Target; switching back promotes the Target to the single source. `control_model` is surfaced by a picker (web `controlnet-select` parity): installed `controlnet`-family models — scoped to the pinned generation host's inventory when known — sorted downloaded-first with missing entries disabled, merged (deduped) with catalog-installed control-net entries from `GET /api/catalog/installed?kind=control-net` (`fetchCatalogInstalled` in `lib/api/catalog.ts`, host-targeted) valued by `primary_path`, an unknown restored value kept selectable, and a **Custom…** option revealing the legacy free-text input.

The earlier image-only upscale description is superseded by cross-media parity: `upscale_model` appears for still and video generation on web, desktop, mobile, and TUI. Stills upscale inline; videos publish the original and then queue a durable Framewise job. Library context menus and full-media/info viewers offer **Upscale…** for images and **Framewise upscale…** for videos through a shared model/progress dialog. First use downloads the selected model on the owning host; durable video work supports pause, resume, cancel, and restart recovery. `POST /api/gallery/upscale` publishes image results and `/api/video-upscale-jobs` owns video processing.

Frame decoding, constant-FPS validation, H.264 encoding, and compatible audio
muxing use a process-isolated FFmpeg bridge on the owning host. Nix packages
bind exact `ffmpeg` and `ffprobe` store paths and the CUDA container installs
them; raw binary hosts advertise video upscale as unavailable when either tool
is absent while preserving server-side image upscale capability.

Post-generation image upscale persists distinct `-original` and `-upscaled` entries on the serving host. Remote-output auto-save mirrors both to This Mac, and gallery reuse restores the pre-upscale generation dimensions rather than the upscaled raster size. If upscaling fails after generation, the job completes with the original image as a single artifact.

`GenerateResponse`: `images[]` (`{data,width,height,index}`), optional `video` (`{data,format,width,height,frames,fps,thumbnail,gif_preview}`), `generation_time_ms`, `model`, `seed_used`, `gpu` (ordinal, multi-GPU).

## 2. Model families & catalog

**Quirks:**

- **LTX-2 is performance-qualified on CUDA and Apple Metal** (measured on the 19B/22B distilled FP8 tiers); CPU is correctness-only. The family has its own MP4+AAC media pipeline. Camera-control LoRA presets currently resolve only Lightricks LTX-2 19B (LTX-2.3 needs explicit .safetensors).
- Video families: `ltx-video`, `ltx2`. Audio: `ltx2` only (mp4 only). Mesh: `hunyuan3d` only (glb only; obj, stl and ply are export transcodes, never stored formats).
- **`hunyuan3d` is canvasless, maskless, strengthless and promptless, and the generation profile says all four.** Its recipe advertises `resolution.domain: "none"` with zero default width and height (the t2a precedent), `mask.mode: "hidden"`, `supports_strength: false`, `prompt.mode: "ignored"` (the family has no text encoder), and a `mesh` control block carrying the octree allowlist, the iso-threshold float control, the face bounds and a hidden `texture` control. A client renders those instead of a resolution picker and must not re-derive any of it from the family name. `GuidanceCapabilities::for_recipe` answers `ADJUSTABLE_NO_NEGATIVE`, so guidance is offered and the negative prompt is not.
- **A format a recipe does not advertise is a 422 at durable admission**, named `requests[N]: output format 'x' is not available for this recipe`, rather than a row that holds and then fails. `hunyuan3d` is the one exception: it has a single deliverable container, so an explicit raster format is PINNED to `glb` — an older client that always sends `png` still gets its mesh.
- **Mesh export is a transcode of the stored GLB, on every surface.** `POST /api/gallery/export/:filename` takes `glb`, `obj`, `stl` or `ply` for a `.glb` source and answers with an attachment; `capabilities.mesh.export_formats` advertises the list, absence reading as no export. The gallery file is never renamed or replaced.
- **A mesh print records the controls that rendered.** `OutputMetadata.mesh` (additive, `Option<MeshRequestOptions>`) is written by `OutputMetadata::from_generate_request` for every request that carries a `mesh` block, names a mesh container, or resolves to the mesh family: `octree_resolution` and `threshold` are the request's values or the `validation::MESH_DEFAULT_*` the engine fell back to (`MeshRequestOptions::resolved_with_defaults`), `target_faces` stays as requested because absence IS the rendered choice. Absent on every raster print and on prints saved before the field existed. Reuse settings on every surface restores from it rather than from a form's leftovers.
- **LTX-2 img2video:** `source_image` is staged as frame-0 conditioning with `strength`; the desktop shows the single source well (no mask — pad-repaint isn't offered, a mask-dependent fit policy coerces to crop-fill). Plain `ltx-video` has no img2vid path in the engine, so the well never renders for it.
- Z-Image has a bespoke quantized transformer (GGUF naming differs from BF16).
- Flow-matching families (FLUX, SD3, Z-Image, Flux.2, Qwen-Image) ignore scheduler.
- H.264 decode baseline for LTX-2 source ingest; `mp4` feature only gates AAC mux.

## 3. Model management

- **list** (`mold list`/`ls`, `GET /api/models`): installed models + disk usage + available-to-pull.
- **pull** (`mold pull <model>`, `POST /api/models/pull`, SSE `/api/downloads/stream`): download with live progress; `--skip-verify` (SHA-256), `--accept-license <ID>` to record acceptance of a third-party asset licence such as `insightface-antelopev2` before the pull it unblocks. Auto-pull on generate if missing (server or local fallback). HF_TOKEN / CIVITAI_TOKEN for gated repos.
- **rm** (`mold rm <model...>`/`remove`; the HTTP peer is `DELETE /api/models/:model`, and `DELETE /api/models/unload` is the separate GPU-unload route): removes the paths `mold_core::removal::model_owned_paths` says the model owns; shared files (VAE/CLIP) kept until unreferenced; `--force` skips confirm. The route answers 409 while the model is GPU-resident.
- **info** (`mold info [model]`, `--verify`): model details or install overview; SHA-256 integrity verify. `GET /api/models/:model/components`. Desktop's Installed → Info expansion shows per-component present/missing dots and offers a per-missing-component **Repair** button that enqueues a catalog download keyed on the component's `repair_model` against the same host the listing came from (only missing files are re-fetched — no delete + re-pull); web instead deep-links to the catalog search.
- **licenses** (`mold licenses [--local]`, `GET /api/licenses`): every known third-party model licence and whether the answering host has accepted it. Acceptance is per Mold data root, so a fleet client asks each machine; advertised by `capabilities.licenses`.
- **license acceptance** (`mold licenses accept <ID>...`, `POST /api/licenses/accept`): records consent without downloading the bundle. Settings offers it beside review-and-download, and the desktop panel has a machine selector so consent can be recorded on a remote host. Installing a gated model from the Models page, and generating with one, both raise the shared consent dialog against the host that will do the downloading.
- **stats** (`mold stats`, `--json`): disk usage for models/output/logs/shared components.
- **clean** (`mold clean`, `--force`, `--older-than 30d`): dry-run by default; stale `.pulling` markers (>6h), orphaned shared files, hf-cache transients, old output images.
- **load/unload** (`mold unload`, `POST /api/models/load`, `DELETE /api/models/unload`): free GPU memory.
- **ps** (`mold ps`, `GET /api/status`): server status + loaded models.
- **download monitoring (web/native apps)**: `GET/POST /api/downloads`, `DELETE /api/downloads/:id`, and the live SSE stream expose cancelable progress. Desktop keeps a stream for every ready host, pins rows in Models, mirrors them in host detail, shows status/current file/files done/total/live ETA, and retains settled History with same-host Retry. iPhone keeps the same multi-host stream ownership within Models and host detail, with immediate Pull button status and cancellation. The web drawer remains scoped to its serving host.
- **automatic generation routing (desktop, web, iPhone)**: one policy in `studio/lib/hostRouting.ts` — model-aware Auto (least busy among the machines that already have the model), Most capable (CUDA > Metal > unknown, then VRAM, then queue, inferring the backend from the GPU name on servers that predate `gpu_info.backend`), target normalization, the fleet model union, and the frozen host choice. `desktop/src/lib/hosts.ts` and `web/src/lib/hostRouting.ts` re-export it, binding only their own home host (the built-in engine / the origin) as the dead-heat winner. Generation never waits for a placement preview: pinned work submits directly, while Auto and Most capable choose from cached model/queue/GPU telemetry and durably admit to that frozen host. The placement preview remains the sequence planner. iPhone has no home host: `desktop/src/mobile/generateTarget.ts` persists its policy at `mold.mobile.generate-target.v1`, offers Auto and Most capable only while two or more connected machines are reachable, unions the model picker across them, and freezes the winner into the same immutable route record the pinned path uses.
- **reference-media selection and staged routing (desktop, web, iPhone)**: the established image picker has single- and ordered multi-image modes, reads from the unified gallery across all connected hosts, retains local-file input, and is reused by ordinary source/keyframe wells and MiniMax H3 Ref2VA. Ref2VA chooses a compatible model host before uploading its ordered references and relies on that host's exact staged-media admission before queueing; its placement preview is intentionally non-authoritative until staging, while identity requests remain fail-closed on the frozen machine's own advertised identity support.
- **multi-host Installed shelf (desktop and iPhone)**: merges every ready/saved host's `/api/models` result, deduplicates equal names, collects host badges, and routes model actions to the owning host. Desktop prefers its local copy when several hosts have one; both host-detail surfaces fetch fresh host-scoped inventory. Because the row is merged, its `installed` marker never suppresses the install action: a model on one machine keeps an **Install** action for every reachable machine that lacks it (desktop's Installed rows carry it directly), and only a model every reachable machine owns is repair-only.
- **multi-host Sequences (desktop)**: the Create Output setting merges installed video models from every ready host and routes chain limits, creation, durable job actions, SSE progress, and stage previews to the host selected for that model. Remote CUDA LTX-2 stays available when the built-in Mac engine is Metal.
- **boot reconnect (desktop)**: every `savedHosts` entry is attempted immediately on each launch, concurrently with local-engine startup. `connectedHostIds` is retained for migration/order compatibility but never suppresses a remembered host; failed probes remain visible and polling retries them.
- **SIZE vs FETCH semantics**: catalog entries distinguish declared size vs actual fetch. Installed rows separately label primary checkpoint **weights** (`size_gb`) and the larger footprint **with shared runtime** (`disk_usage_bytes`, including referenced shared encoders/VAEs); the all-host header does not sum per-model runtime footprints because that would double-count shared files.
- **safe manifest pull targets (native apps)**: runnable built-in variants precede live Hugging Face results; aggregate `separated` checkpoint repositories and repositories already represented by the manifest are suppressed so one click cannot accidentally fetch every checkpoint in a multi-model LTX repository.

## 4. Gallery / media management

The desktop **Choose from gallery…** square grid follows the Library's performance contract: it virtualizes to visible rows plus overscan, keeps off-screen rows keyboard-reachable, and passes each print's media-version identity and visible/near priority into the shared persistent thumbnail path. Its image-only filter requires the stored filename and gallery metadata to agree on PNG/JPEG, so a mislabelled video cannot be attached to an image input.

- **Browse** (web `LibraryPage.vue` + `gallery/GalleryGrid.vue`, `GET /api/gallery`): returns `GalleryImage[]` = `{filename, metadata (OutputMetadata), timestamp, format, size_bytes, metadata_synthetic, media_version}` — `media_version` is the key every persistent thumbnail cache is keyed on, plus the organization fields below.
- **Image/thumbnail** URLs: `GET /api/gallery/image/:filename`, `/api/gallery/preview/:filename`, thumbnail endpoint.
- **Delete**: `DELETE /api/gallery/image/:filename` — always enabled (`capabilities.gallery.can_delete: true`); pair with `MOLD_API_KEY` if exposed. On current servers it moves the print to the host's trash (`<output_dir>/.trash/` + `generations.trashed_at_ms` + tombstone); `?permanent=true` hard-deletes as before.
- **Library organization + trash (server API; desktop UI follows in the next PR)**: per-host row state served by mold-server and merged client-side like the gallery. `GalleryImage` gains additive `title`, `tags`, `favorite`, `collections`, `trashed_at`, `purge_at`; `GET /api/gallery?view=library|trash`; `PATCH /api/gallery/image/:filename` (`GalleryPatchRequest`); `POST /api/gallery/organize` (bulk); `GET/POST /api/gallery/collections`, `GET/PATCH/DELETE /api/gallery/collections/:id`, `PUT /api/gallery/collections/:id/items {add, remove}`; `GET /api/gallery/tags`, `PATCH/DELETE /api/gallery/tags/:name`; `POST /api/gallery/trash`, `POST /api/gallery/trash/restore` (409 `GALLERY_RESTORE_CONFLICT`), `DELETE /api/gallery/trash` → `{purged}`, `POST /api/gallery/trash/sweep` → `{purged, remaining}`; SSE `gallery_updated` / `gallery_trashed` / `gallery_restored` / `gallery_collections_changed`. Retention is the per-host `gallery.trash_retention_days` config key (default 30, 0 = forever) editable through `/api/config`. `GenerateRequest.title` → `OutputMetadata.title` → row title, slugged into the default filename (`mold-{model}-{ts}~{slug}.{ext}`). CLI: `mold run --title`, `mold trash list|restore|empty|sweep` (`crates/mold-cli/src/commands/trash.rs`); `MoldClient` has typed methods for every endpoint above. Desktop/web/iPhone UI (Prints | Collections | Trash segmented Library, lightbox editing, bulk bar, retention settings) ships in the follow-up PRs.
- **Embedded metadata**: PNG (per-field tEXt/iTXt + composite `mold:parameters` JSON), JPEG (COM marker + XMP APP1 — readable by exiftool/Photoshop/Lightroom/GIMP), mp4/webp/apng/gif carry metadata too. - **Mesh viewing**: a `.glb` cannot be decoded by any raster path, so `MeshData` carries a `poster` PNG rendered at save time and written into the shared thumbnail cache. Grids and the TUI cell show that poster; only the Lightbox mounts `studio/components/MeshViewer.vue`, a dependency-free WebGL2 viewer over a hand-written GLB parser (`studio/lib/glb.ts`) with orbit controls. It validates the container rather than trusting it and falls back to the poster on any failure, so a viewer that cannot start never leaves a black rectangle. Reuse and export are disabled for meshes exactly as they are for audio.
- **Metadata display** (web `gallery/Lightbox.vue`, TUI compact/full details, desktop `components/gallery/Lightbox.vue`, iPhone viewer): full generation params from embedded chunk. The desktop lightbox shows the complete recorded set — prompt, original/expanded prompt, negative prompt, model, seed, resolution, steps · guidance, scheduler, CFG++, img2img strength, frames/fps, pipeline, full LoRA stack (path × scale), file size, format, created time, origin host, and mold version — with conditional rows that only render when a field is present (older servers simply omit newer fields).
- **Reuse settings (desktop)**: full-fidelity. Library tiles and the lightbox hand the composer the item's complete `OutputMetadata` (`composer.set({ metadata })`); `applyMetadataToForm` (`lib/generateForm.ts`) restores prompt, negative/original prompt, pre-upscale generation dimensions, steps, guidance, static seed, scheduler, CFG++, strength, the LoRA stack (capped at `MAX_LORA_STACK`), control/upscale models, output format, and video params (frames/fps/audio/pipeline/spatial/temporal/guidance overrides), while clearing binary media that metadata cannot carry (source/mask/control images, source video, keyframes, audio). ## 8. Queue & job lifecycle

- **Single model at a time**: `tokio::Mutex` + `spawn_blocking`. `AppState.model_cache` = LRU (max 3, `MOLD_MAX_CACHED_MODELS`) with `ModelResidency { Gpu, Parked }` — eviction removes the entry rather than adding a third state, and at most one engine is GPU-resident.
- **Job states** (`JobLifecycle`): `Queued` → `Running`, plus `Paused` (durable work recovered after a restart, listed but never hydrated until an operator resumes it) and `Held` (attempt cap exceeded, or the recorded request could not be reconciled — listed with a `held_reason`, never auto-run, cleared with `DELETE /api/queue/:id` or returned to the queue with `POST /api/queue/:id/retry`); target-GPU editable only while Queued. The durable backlog is uncapped; `--queue-size`/`MOLD_QUEUE_SIZE` (default 200) bounds only the hydrated runtime window, while legacy attached requests can still receive 503 when that window is full. Look-ahead/deferral tuning envs.
- Endpoints: `GET /api/queue`, `PATCH /api/queue/:id` (retarget GPU, or reorder within the queue via `position` — gated by `capabilities.queue.can_reorder`), `GET /api/queue/:id`, `DELETE /api/queue/:id`, `POST /api/queue/:id/retry`, `GET /api/queue/:id/preview`, SSE progress (`generate/stream`, includes `Queued`/step progress). Web reconciles through `web/src/composables/useQueueReconciler.ts` and renders the queue in the Machines workspace plus the shared `studio/components/QueueEntryDetail.vue`.
- **Desktop parity (Jobs view)**: multi-GPU hosts render per-GPU queue lanes (`lib/queueLanes.ts`, sharing the web lane logic). Current servers use the exact schedulable ordinals from authoritative `/api/devices`; older servers fall back to additive `/api/status.gpus`. Queued rows drag between lanes of the **same** host or move via right-click "Move to GPU N"; both call `jobs.reassignGpu` → `PATCH /api/queue/:id` on the owning host, then re-sync from the server (never optimistic; 404/409/422 → error toast + refetch). Cross-host drops are rejected (`resolveDropAction`) — jobs cannot migrate between servers. Queued rows also reorder within a host's queue (`PATCH /api/queue/:id` with `position`, gated by `capabilities.queue.can_reorder`); the shared queue mirrors in the Machines workspace. Single-GPU hosts keep the flat list.
- **Queue row detail (desktop, web, iPhone)**: one shared model — `studio/lib/queueEntryDetail.ts` — behind `studio/components/QueueEntryDetail.vue`, opened from the desktop drawer, the web Machines row, and the iPhone bottom sheet. It renders the prompt, the Create inspector's own setting groups, the shared `resolveQueueWait` waiting vocabulary, and the facts a payload-free durable row still carries (submitted time, durability, replay, dispatch attempts, the plan's lane and estimate), plus a hold reason and error in full with a Copy control and the running row's `GET /api/queue/:id/preview` snapshot. `GET /api/queue` merges the live registry — whose rows carry `metadata` — with the durable SQLite projection, which deliberately never selects `request_json`, so a job admitted through `POST /api/generation-batches` has no listed request until the feeder hydrates it; the panel says so in the machine's own terms and never asks anyone to upgrade a server. Desktop additionally falls back to this app's copy of the request it submitted, so its own work is never blank. Actions route to the exact authenticated host: **Reuse settings** through the same mapper Library Reuse uses, **Cancel** (queued always, running where `capabilities.queue.cooperative_cancellation` is advertised) behind the plain shared confirm on desktop/web and an inline two-step on iPhone, and **Retry** for a held row the host fenced, using the durable batch authority the submitting client holds.
- **iPhone generation queue**: every submitted batch member keeps its own remote target, POST-SSE lifecycle, progress label, result, and Cancel action. The composer remains available while work is queued; concurrent streams are capped so held generation connections do not starve gallery/download traffic.
- **Live latent previews** (`preview` SSE progress events, FLUX.1/Flux.2/Z-Image/Wan — Wan projects the clip's middle latent frame; `MOLD_STEP_PREVIEW=0` disables): rendered on **all four interactive app surfaces**. Desktop (`GenerateView.vue`) and iPhone (`MobileApp.vue` develop bed above the status line) reduce them through the shared `generationJob.ts` (`previewUrl` blob URL, revoked on replace); web types the event in `SseProgressEvent` and reduces it in `useGenerateStream.ts` as a data URI (`previewUrl`, never persisted, cleared on settle). Those graphical surfaces layer the preview under the shared `@ui` DevelopCanvas grain with the same math — preview blur `max(2, 14 − 12·p)`, grain opacity `max(0.18, 1 − 0.9·p)` — and the web/iPhone develop beds adopt the submitted print's aspect ratio. TUI decodes the same bounded PNG into separate transient state, replaces a geometry-keyed fixed-protocol cache, centers it for Kitty/Sixel/iTerm2, and retains a one-row denoise readout; malformed frames keep the last valid image and settle/error clears it. The plain CLI intentionally remains text-only because it has no persistent image canvas. Web's seed section also gains desktop's "lock last (seed)" affordance (`ControlsAside.vue`, `lastSeed` from the most recent completed job).
- **Generation estimate**: `POST /api/generate/estimate` (VRAM/time preflight).

## 9. Config & settings system

**Two stores, one `Config` view (profile-scoped):**

- `config.toml` at `$MOLD_HOME/config.toml` (default `~/.mold/`; `~/.config/mold/home` is only a bootstrap pointer file naming a non-default root — `website/guide/configuration.md` is canonical): bootstrap — `config_version`, `default_model`, `models_dir`, `server_port`, `default_width/height/steps`, `embed_metadata`, `t5_variant`/`umt5_variant`/`qwen3_variant`, `output_dir`, `media_roots`, `default_negative_prompt`, `[expand]`, `[scheduler]`, `[gallery]` (trash retention), `[queue]` (held retention), `[generate]` (`auto_tag_title`), `[logging]` (level/file/dir/max_days), `[runpod]`, `[lambda]`, `gpus`, `queue_size`, per-model `[models.<name>]` component paths + defaults (transformer/vae/encoders/steps/guidance/width/height/frames/fps/scheduler/lora/placement/etc.).

Known keys: `tui.theme/last_model/last_prompt/last_negative/negative_collapsed/negative_cleared/view_mode/gallery_columns/advanced_open/advanced_section/confirm_destructive/default_format/generate_target/reduce_motion/show_timeline`, `expand.*` (enabled/temperature/top_p/max_tokens/thinking/system_prompt/batch_prompt/backend/model/api_model/families_json), `generate.default_width/height/steps/default_negative_prompt/embed_metadata/auto_tag_title`, `chain.jobs_artifact_ttl_days`, `gallery.trash_retention_days` (Library trash retention, 0 = forever, default 30), `queue.held_retention_days` (durable held-row and settled-batch retention, 0 = forever, default 30), `profile.active`.
- `MOLD_*` env (highest precedence) — ~120 vars.

**CLI** (`mold config`): `list [--json]` (tags rows `[db]`/`[file]`/`[env]`), `get <key> [--raw]`, `set <key> <val>` (routes by prefix — `expand.*`→DB, `models_dir`→TOML; `none` clears), `path`, `edit` ($EDITOR), `where <key>` (which surface owns it), `reset <key>|--all [--yes]` (drop DB key → fall back). `--profile <name>` global override. Multi-profile keyed on `(profile,key)`; resolves `MOLD_PROFILE`→`settings.profile.active`→`default`. One-shot idempotent config.toml→DB migration on first boot. Web `SettingsPage.vue` (with `ConfigSettingsPanel.vue`) and `GenerationTemplatesPanel.vue` (saved param presets); desktop `TemplatesPanel.vue` (parity — `localStorage` key `mold.desktop.generation.templates.v1`, base64 media stripped on save).

**iPhone app settings:** `mold.mobile.settings.v1` stores four validated
fields — `theme` (`system|dark|light`), `themeFamily` (`mold|safelight`),
`autoSavePhotos`, and `autoTagTitle` — defaulting fresh installs to Dark +
Safelight with Photos auto-save and title auto-tagging both on, while
preserving valid saved choices (`website/guide/iphone.md` is canonical for the
user-facing defaults).
`src/lib/theme.ts` is the shared desktop/mobile contract. Mobile
applies it before Vue mounts, serializes/coalesces native appearance calls, and
maps the final value to UIKit plus a status-bar refresh. Host metadata and the
selected host use separate local-storage keys; API keys remain in Keychain and
mobile templates use `mold.mobile.generation.templates.v1`.

**Metadata DB**: `MOLD_HOME/mold.db` (`MOLD_DB_PATH` override, `MOLD_DB_DISABLE=1`). `SCHEMA_VERSION` 33 with forward-only migrations. Twenty-three tables: `generations`, `generation_tags`, `tags`, `collections`, `collection_items` (Library organization), `settings`, `settings_v`, `model_prefs`, `model_prefs_v`, `prompt_history`, `catalog`, `chain_jobs`, `chain_job_stages`, `generation_queue`, `generation_queue_media`, `generation_batches`, `generation_batch_children` (the durable queue), `gallery_media_sets`, `gallery_media_bindings` (repairable retained source-media projection), `gallery_mutation_receipts`, `device_preferences`, `paired_clients`, and `scheduler_estimates`.

## 10. Remote vs local modes

- **Remote** (default): HTTP to `MOLD_HOST` (default `http://localhost:7680`). SSE streaming with blocking fallback.
- **Desktop local server:** the desktop always keeps this Mac online as the app's permanent primary engine — remote servers are only ever host-list entries (the Machines workspace), deduped by server instance UUID with hostname-based display names; a boot migration re-homes old remote-primary installs. It reuses an existing local server or starts an authenticated wildcard-bound server on port 7680 (advertised ephemeral fallback on conflict), publishes `_mold._tcp` (including an `id` instance TXT record), and exposes its persistent API key in the Machines workspace. Every connected host's models participate in the installed-model union; the first-model screen appears only after all connected hosts report zero installed generation models.
- **iPhone remote-only app:** every host adapter remains `kind: "remote"` and `primary: false`; the mobile crate cannot start or embed an engine. Hosts are added through Apple Bonjour, an IP/DNS/HTTPS address, or a Tailscale MagicDNS name, with per-host keys in iOS Keychain. Host detail owns telemetry, models-disk, queue, downloads, loaded models, and installed inventory. Main content disables document zoom and overscroll bounce instead of exposing desktop's 80–130% interface scaling; only the Library viewer reserves its horizontal swipe gesture.
- **Local fallback**: server unreachable → local GPU (auto-pulls missing model).
- **Forced local**: `--local` skips server (requires GPU-feature build; errors gracefully otherwise).
- **Server**: `mold serve` (`--port`/`MOLD_PORT`, `--bind`, `--models-dir`, `--log-format json|…`, `--log-file`, `--gpus`, `--queue-size`, `--discord`, `--no-mdns`). Managed daemon: `mold server start|status|stop|discover` (`start` takes `--port`, `--bind`, `--models-dir`, `--log-file` — on by default — and `--no-mdns`; `discover` browses `_mold._tcp` with `--timeout-secs`, `--json`, `--probe`). Auth via `MOLD_API_KEY`; CORS `MOLD_CORS_ORIGIN`; rate limit `MOLD_RATE_LIMIT`/`_BURST`. `GET /api/resources` + `/stream` (GPU/VRAM/CPU live), `/api/capabilities`, `/api/status`, `/health`, `/api/openapi.json`, `/api/docs` (Scalar), `POST /api/shutdown`.
- **Cloud provisioning**: the desktop RunPod workspace covers API setup, account/spend status, GPU stock, geographically labeled datacenters, full network-volume lifecycle management (create, select, rename/grow, delete), pod create/start/stop/delete, RunPod console handoff for logs, automatic refresh, and connecting the app to a pod. The volume form only offers datacenters that support persistent volumes. Volume selection persists across app launches and automatically enforces Secure Cloud plus the volume's datacenter. Network-volume pods omit unsupported stop/start actions; deleting their compute instance preserves `/workspace` on the volume. The CLI additionally provides doctor/get/usage and `runpod run` one-shot generation on fresh/warm pods. Lambda provisioning remains CLI-only (doctor/availability/deploy tunneled web UI/status/logs/tunnel/ssh/filesystems/terminate/reset).
- **Interface scaling**: ⌘+/⌘−/⌘0, the native View menu, and Settings → Appearance & app scale the entire webview from 80–130%. The preference persists, and fixed overlays plus custom context menus remain viewport-clamped at every level.
- **Native image clipboard**: right-click Copy image is available from Library tiles, the Library lightbox, and completed Create canvases. Images are copied at full resolution; video copy remains intentionally disabled.
- **MCP server**: `mold mcp [--host]` — stdio MCP for LM Studio / MCP hosts (thirteen tools: generation, mesh, mesh export, async status/retry, gallery, models, LoRAs, server status, `expand_prompt`, `remix_prompt`; prompting guides as `mold://prompting/` resources; requires running `mold serve`). `generate_mesh`'s `octree` / `threshold` / `target_faces` schema is built from the same `validation::MESH_*` constants the profile advertises, and its description points at `export_mesh` for OBJ / STL / PLY.
- **TUI 3-D generation**: the Create form reads the selected recipe's profile — a `mesh` block adds an Advanced ▸ **3-D mesh** section (Octree over the advertised allowlist, Iso threshold, Target faces; absent-until-touched, defaults shown from the profile), pins the Format row to GLB, and hides Strength / Mask / Negative when the profile says so; `prompt.mode = ignored` lets Generate submit with an empty prompt. A finished mesh saves the `.glb`, caches its poster under the gallery thumbnail key, previews the poster, and captions with `tris · verts · bounds`. The Library never hands a `.glb` to a raster decoder (poster from the thumbnail route), and `x` on a `.glb` opens an export picker (OBJ / STL / PLY, from the owning host's `capabilities.mesh.export_formats` or the in-process writer for a local print) that writes beside the TUI's other saves.
- **Discord 3-D generation**: `/generate` with a Hunyuan3D model and a `source_image` delivers GLB (the format option is ignored, mirroring the server's pin), needs no prompt (the option is optional whenever a source image is attached — Discord cannot make it optional per model), posts the poster as the embed image with the `.glb` attached beside it (an oversized mesh posts the poster alone with a note), and summarises as **Mesh Generated** with triangles, vertices, bounds, format, and seed.
- **Upscale** standalone: `mold upscale <img|-> [-m model] [-o] [--format png|jpeg] [--tile-size] [--host] [--local] [--preview]`; `POST /api/upscale` + `/stream`.
- **Self-update**: `mold update [--check] [--force] [--version vX]` (GitHub release, SHA256-verified; bows out on distro `/usr/bin/mold` linker collision).
- **Shell completions**: `mold completions <shell>` (bash/zsh/fish/elvish/powershell) + dynamic model-name completion.
