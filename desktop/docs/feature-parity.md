# mold — User-Facing Feature Inventory (native-app parity)

Sources of truth: CLI clap defs (`crates/mold-cli/src/main.rs`), core wire types (`crates/mold-core/src/types.rs`), shared desktop/mobile capability and request logic (`desktop/src/lib/`), desktop UI (`desktop/src/`), iPhone UI (`desktop/src/mobile/`), native iOS bridges (`apps/mobile/src-tauri/`), server routes (`crates/mold-server/src/routes.rs`), catalog (`crates/mold-catalog/`), config (`crates/mold-core/src/config.rs`, `crates/mold-db/src/settings.rs`), chain (`crates/mold-core/src/chain.rs`, `chain_toml.rs`), Discord (`crates/mold-discord/src/commands/`), and TUI (`crates/mold-tui/src/`).

Frontend parity is maintained through the repo-root Bun workspace: `studio/`
owns browser-safe current-contract transport, Pinia state, and shared domain
logic; `ui/` owns tokens and low-level primitives; `web/` and `desktop/` own
surface navigation and platform adapters. Web intentionally requires current
server and storage schemas, while desktop and iPhone retain native
compatibility normalization. Browser routes are `/create`, `/library`,
`/models`, `/machines`, and `/settings`; retired routes are not redirected.

CLI-only extras layered on top: `--clip-frames`, `--motion-tail` (chain tuning), `--frames-per-clip` (multi-prompt sugar), `--lora-scale`, text-encoder variant flags (§6), `--eager`, `--offload`. `--camera-control` (LTX-2 camera LoRA presets: dolly-in/-left/-out/-right, jib-down/-up, static, or an explicit `.safetensors` path) has desktop parity — see the Camera motion select below.

Desktop parity: `upscale_model` is surfaced by the always-visible icon-led "Upscale" select in Advanced on desktop and web (image families only; explicit Off option; lists every known upscaler from `/api/models`, downloads on first use on the selected generation host, including multi-GPU remotes), and the gallery's right-click **Upscale** action drives `POST /api/upscale` directly, saving the result to the local gallery (`/api/upscale` does not persist server-side). `source_image` / `mask_image` are surfaced by `SourceImageWell.vue` — a **Choose from gallery…** picker (`ImagePickerModal.vue` — upload, or the same merged multi-host gallery as the Gallery's All view: every connected host's still images deduped by the gallery store, tiles labeled with their host when more than one source exists, bytes fetched from the print's own origin host) plus an **Edit mask…** brush/erase canvas (`MaskEditorModal.vue`, invert / clear / undo-redo cap 20 → white-on-transparent PNG). A **Source fit** selector (web parity: `sourceFit.ts` is a verbatim port) picks how a source that doesn't match the requested width×height maps onto the canvas — Pad repaint (default; generated white pad-band mask → repaint), Crop fill, Pad fit, Lanczos resize, or Upscale then fit (`POST /api/upscale/stream` preprocessing seeded from the post-generate upscaler pick). Fitting runs client-side on submit (`sourceFitPreprocess.ts` + `sourceFitCanvas.ts`); an existing inpaint mask is refit through the same transform, and the generation host is resolved BEFORE preprocessing so a cache miss for the pre-fit upscale (and its model auto-pull) lands on the host the job routes to. Desktop, web, and iPhone each keep a per-composer single-entry cache: the deterministic upscale result survives target-size and route changes, while the fitted source/mask is keyed by source, mask, policy, and target size; in-flight Batch siblings share the same pass and failed entries remain retryable. The LTX-2 advanced fields (`pipeline`, `spatial_upscale`, `temporal_upscale`, `retake_range`, `source_video`, `keyframes`, `guidance_overrides`, and `audio_file` for the a2vid pipeline) render directly in the always-open Video section (ltx2 family only, gated by `capabilities.supportsAdvancedVideo`; kebab-case enum values, nulls omitted, pruned on family change). The gallery image picker (`ImagePickerModal.vue`) filters its grid to PNG/JPEG, the only still formats the generate endpoints accept. Keyframe frame indices follow the web SPA (0-based, +24 suggestion) — not the 8n+1 total-frame-count constraint. A **Camera motion** select in the video section (ltx2 only) surfaces the host-compatible camera-control LoRAs plus a custom `.safetensors` path. Built-ins are reported by `/api/capabilities/ltx2-camera-controls`, remain selectable before installation, and download on first use on the exact generation host. One-shot requests append `{ path: "camera-control:<preset>" | <raw path>, scale: 1.0 }` to `loras[]`; sequence Advanced stores the choice per clip and writes the same entry to that stage's `loras[]`, so different clips may use different moves. Hosts with no compatible built-ins (currently LTX-2.3) keep the custom-path escape hatch instead of rendering disabled options.

Desktop parity: `edit_images` is surfaced by `SourceImageWell.vue`'s qwen-edit branch — when `capabilities.sourceImageMode === "qwen-edit"` the single source well is replaced by a reorderable picture strip (index 0 = **Target**, rest = **References**; role/title labels and reorder semantics ported from the web Composer via `lib/editAttachments.ts`), fed by the multi-select `ImagePickerModal.vue` with drag or ‹ › reordering and per-tile remove. The ordered strip ships verbatim as `edit_images` (`form.imageAttachments` → `buildRequest`), batch is locked to 1, and `pruneRequestForFamily` now KEEPS `edit_images` for qwen-edit (it used to strip the image entirely — even single-image edits were broken) while stripping it from every other family and never letting `source_image`/`strength` through for qwen-edit. Switching single→qwen-edit seeds the strip with the attached source as Target; switching back promotes the Target to the single source. `control_model` is surfaced by a picker (web `controlnet-select` parity): installed `controlnet`-family models — scoped to the pinned generation host's inventory when known — sorted downloaded-first with missing entries disabled, merged (deduped) with catalog-installed control-net entries from `GET /api/catalog/installed?kind=control-net` (`fetchCatalogInstalled` in `lib/api/catalog.ts`, host-targeted) valued by `primary_path`, an unknown restored value kept selectable, and a **Custom…** option revealing the legacy free-text input.

Post-generation upscale persists distinct `-original` and `-upscaled` entries on the serving host. Remote-output auto-save mirrors both to This Mac, and gallery reuse restores the pre-upscale generation dimensions rather than the upscaled raster size. If upscaling fails after generation, the job completes with the original image as a single artifact.

`GenerateResponse`: `images[]` (`{data,width,height,index}`), optional `video` (`{data,format,width,height,frames,fps,thumbnail,gif_preview}`), `generation_time_ms`, `model`, `seed_used`, `gpu` (ordinal, multi-GPU).

**Quirks:**

- **LTX-2 is CUDA-only** for real generation (CPU correctness-only, Metal unsupported). Has its own MP4+AAC media pipeline. Camera-control LoRA presets currently resolve only Lightricks LTX-2 19B (LTX-2.3 needs explicit .safetensors).
- Video families: `ltx-video`, `ltx2`. Audio: `ltx2` only (mp4 only).
- **LTX-2 img2video:** `source_image` is staged as frame-0 conditioning with `strength`; the desktop shows the single source well (no mask — pad-repaint isn't offered, a mask-dependent fit policy coerces to crop-fill). Plain `ltx-video` has no img2vid path in the engine, so the well never renders for it.
- Z-Image has a bespoke quantized transformer (GGUF naming differs from BF16).
- Flow-matching families (FLUX, SD3, Z-Image, Flux.2, Qwen-Image) ignore scheduler.
- H.264 decode baseline for LTX-2 source ingest; `mp4` feature only gates AAC mux.

## 3. Model management

- **list** (`mold list`/`ls`, `GET /api/models`): installed models + disk usage + available-to-pull.
- **pull** (`mold pull <model>`, `POST /api/models/pull`, SSE `/api/downloads/stream`): download with live progress; `--skip-verify` (SHA-256). Auto-pull on generate if missing (server or local fallback). HF_TOKEN / CIVITAI_TOKEN for gated repos.
- **rm** (`mold rm <model...>`/`remove`, `DELETE /api/models/unload` is separate): removes model + unique files; shared files (VAE/CLIP) kept until unreferenced; `--force` skips confirm.
- **info** (`mold info [model]`, `--verify`): model details or install overview; SHA-256 integrity verify. `GET /api/models/:model/components`. Desktop's Installed → Info expansion shows per-component present/missing dots and offers a per-missing-component **Repair** button that enqueues a catalog download keyed on the component's `repair_model` against the same host the listing came from (only missing files are re-fetched — no delete + re-pull); web instead deep-links to the catalog search.
- **stats** (`mold stats`, `--json`): disk usage for models/output/logs/shared components.
- **clean** (`mold clean`, `--force`, `--older-than 30d`): dry-run by default; stale `.pulling` markers (>6h), orphaned shared files, hf-cache transients, old output images.
- **load/unload** (`mold unload`, `POST /api/models/load`, `DELETE /api/models/unload`): free GPU memory.
- **ps** (`mold ps`, `GET /api/status`): server status + loaded models.
- **download monitoring (web/native apps)**: `GET/POST /api/downloads`, `DELETE /api/downloads/:id`, and the live SSE stream expose cancelable progress. Desktop keeps a stream for every ready host, pins rows in Models, mirrors them in host detail, shows status/current file/files done/total/live ETA, and retains settled History with same-host Retry. iPhone keeps the same multi-host stream ownership within Models and host detail, with immediate Pull button status and cancellation. The web drawer remains scoped to its serving host.
- **multi-host Installed shelf (desktop and iPhone)**: merges every ready/saved host's `/api/models` result, deduplicates equal names, collects host badges, and routes model actions to the owning host. Desktop prefers its local copy when several hosts have one; both host-detail surfaces fetch fresh host-scoped inventory. Because the row is merged, its `installed` marker never suppresses the install action: a model on one machine keeps an **Install** action for every reachable machine that lacks it (desktop's Installed rows carry it directly), and only a model every reachable machine owns is repair-only.
- **multi-host Sequences (desktop)**: the Create Output setting merges installed video models from every ready host and routes chain limits, creation, durable job actions, SSE progress, and stage previews to the host selected for that model. Remote CUDA LTX-2 stays available when the built-in Mac engine is Metal.
- **boot reconnect (desktop)**: every `savedHosts` entry is attempted immediately on each launch, concurrently with local-engine startup. `connectedHostIds` is retained for migration/order compatibility but never suppresses a remembered host; failed probes remain visible and polling retries them.
- **SIZE vs FETCH semantics**: catalog entries distinguish declared size vs actual fetch. Installed rows separately label primary checkpoint **weights** (`size_gb`) and the larger footprint **with shared runtime** (`disk_usage_bytes`, including referenced shared encoders/VAEs); the all-host header does not sum per-model runtime footprints because that would double-count shared files.
- **safe manifest pull targets (native apps)**: runnable built-in variants precede live Hugging Face results; aggregate `separated` checkpoint repositories and repositories already represented by the manifest are suppressed so one click cannot accidentally fetch every checkpoint in a multi-model LTX repository.

**Prompt expansion** (`mold expand`, `POST /api/expand`, web `ExpandModal.vue`): LLM expands a short prompt into detailed generation prompt(s), model-aware style.

Env: `MOLD_EXPAND*`.
- Inline on generate via `--expand`; batch expansion produces per-image prompt variations.
- Web (`ExpandModal.vue`): variations 1/3/5, Preview → clickable candidate list, advanced family override.
- Desktop (`ExpandControl.vue`, `PreparedExpansionBatch.vue`, `ExpansionPullStatus.vue`): Batch is a directly editable positive count with no ordinary eight-print ceiling. One reviewed set has a 10,000-variation memory-safety ceiling, while accepted sets have no cumulative queue limit. Batch 1 keeps one-shot ⌘E in-place rewrite with restore-to-original undo and freezes its resolved route through Generate. If its model/family/host inputs become stale, an immediate larger-copy recovery notice offers Re-expand from the original and Generate, Generate the visible rewrite anyway on the current route, or Restore original; error notices expose a copy control. Batch N greater than 1 resolves one concrete Create host, requires exactly N distinct non-empty results, and opens an inline editor before queuing. Counts above eight initially show eight editors and a compact remainder summary; Review all uses bounded pages. Removal updates Batch; reducing two prompts to one requires an explicit inline confirmation. Regenerate-all replaces the set only after success, while source/model/host/count changes preserve it with named stale reasons. Every sibling uses the stored route, its edited prompt, the shared source prompt as `original_prompt`, and additive `batch_id`/`batch_index`/`batch_count` provenance. Queue acceptance releases Create immediately so another batch can be prepared while earlier work runs; late older completions cannot replace newer recovery authority. Missing expansion-model recovery never falls back or loses the ordered prompts; it reuses the exact host's download store to show Connecting, Starting, Queued, detailed Pulling progress, Ready, and terminal retry inline. Generation chrome resolves catalog wire IDs to human-readable inventory names on every surface.
- iPhone (`MobilePromptTools.vue`, `MobilePreparedExpansionBatch.vue`, `MobileExpansionPullStatus.vue`): Batch uses the same directly editable count, compact first-eight summary, and bounded Review all pages. Batch 1 keeps quick rewrite/undo and freezes the selected host ID, URL, Keychain key, and instance through Develop. Batch N requires exactly N distinct non-empty prompts before a touch-native review workspace appears; edit/remove, explicit two-to-one collapse, regenerate, refresh, discard, named stale reasons, preprocessing guards, and conditional focus restoration mirror the desktop lifecycle without importing its primary-host stores. `useMobileDownloadsStore` is the sole Models/Create progress authority for exact-host recovery: one immutable original-input/route record survives while a per-attempt frozen lease joins compatible Models work already in Starting, temporarily owns the exact route, and releases on terminal/error/stale/superseded/aborted outcomes before Retry reacquires it. Prepared edits/removals cancel pending replacement ownership. Queue acceptance leaves the composer available for another batch. Partial results announce each failed one-based variation and reviewed prompt plus any separate unconfirmed-cancellation caveat while keeping successful output; Library shows batch/source details.

Its simplified essentials are the default; the Advanced toggle extends capability-gated, always-open icon sections below them in the same scrolling inspector without an overlay or canvas dimming. Web uses the same section headers and icons.

## 8. Queue & job lifecycle

- **Single model at a time**: `tokio::Mutex` + `spawn_blocking`. `AppState.model_cache` = LRU (max 3, `MOLD_MAX_CACHED_MODELS`) with `ModelResidency { Gpu, Parked, Unloaded }` — at most one GPU-resident.
- **Job states** (`JobLifecycle`): `Queued` → `Running`; target-GPU editable only while Queued. Queue max size (`--queue-size`/`MOLD_QUEUE_SIZE`, default 200) → 503 when full. Look-ahead/deferral tuning envs.
- Endpoints: `GET /api/queue`, `PATCH /api/queue/:id` (retarget GPU, or reorder within the queue via `position` — gated by `capabilities.queue.can_reorder`), SSE progress (`generate/stream`, includes `Queued`/step progress). Web `RunningStrip`, `RunningJobCard`, `JobsPanel`, `useQueue`, `useQueueReconciler`.
- **Desktop parity (Jobs view)**: multi-GPU hosts render per-GPU queue lanes (`lib/queueLanes.ts`, ported from web `RunningStrip` lane logic). Current servers use the exact schedulable ordinals from authoritative `/api/devices`; older servers fall back to additive `/api/status.gpus`. Queued rows drag between lanes of the **same** host or move via right-click "Move to GPU N"; both call `jobs.reassignGpu` → `PATCH /api/queue/:id` on the owning host, then re-sync from the server (never optimistic; 404/409/422 → error toast + refetch). Cross-host drops are rejected (`resolveDropAction`) — jobs cannot migrate between servers. Queued rows also reorder within a host's queue (`PATCH /api/queue/:id` with `position`, gated by `capabilities.queue.can_reorder`); the shared queue mirrors in the Machines workspace. Single-GPU hosts keep the flat list.
- **iPhone generation queue**: every submitted batch member keeps its own remote target, POST-SSE lifecycle, progress label, result, and Cancel action. The composer remains available while work is queued; concurrent streams are capped so held generation connections do not starve gallery/download traffic.
- **Live latent previews** (`preview` SSE progress events, FLUX.1/Flux.2/Z-Image; `MOLD_STEP_PREVIEW=0` disables): rendered on **all three app surfaces**. Desktop (`GenerateView.vue`) and iPhone (`MobileApp.vue` develop bed above the status line) reduce them through the shared `generationJob.ts` (`previewUrl` blob URL, revoked on replace); web types the event in `SseProgressEvent` and reduces it in `useGenerateStream.ts` as a data URI (`previewUrl`, never persisted, cleared on settle). Every surface layers the preview under the shared `@ui` DevelopCanvas grain with the same math — preview blur `max(2, 14 − 12·p)`, grain opacity `max(0.18, 1 − 0.9·p)` — and the web/iPhone develop beds adopt the submitted print's aspect ratio. Web's seed section also gains desktop's "lock last (seed)" affordance (`ControlsAside.vue`, `lastSeed` from the most recent completed job).
- **Generation estimate**: `POST /api/generate/estimate` (VRAM/time preflight).

## 10. Remote vs local modes

- **Remote** (default): HTTP to `MOLD_HOST` (default `http://localhost:7680`). SSE streaming with blocking fallback.
- **Desktop local server:** the desktop always keeps this Mac online as the app's permanent primary engine — remote servers are only ever host-list entries (the Machines workspace), deduped by server instance UUID with hostname-based display names; a boot migration re-homes old remote-primary installs. It reuses an existing local server or starts an authenticated wildcard-bound server on port 7680 (advertised ephemeral fallback on conflict), publishes `_mold._tcp` (including an `id` instance TXT record), and exposes its persistent API key in the Machines workspace. Every connected host's models participate in the installed-model union; the first-model screen appears only after all connected hosts report zero installed generation models.
- **iPhone remote-only app:** every host adapter remains `kind: "remote"` and `primary: false`; the mobile crate cannot start or embed an engine. Hosts are added through Apple Bonjour, an IP/DNS/HTTPS address, or a Tailscale MagicDNS name, with per-host keys in iOS Keychain. Host detail owns telemetry, models-disk, queue, downloads, loaded models, and installed inventory. Main content disables document zoom and overscroll bounce instead of exposing desktop's 80–130% interface scaling; only the Library viewer reserves its horizontal swipe gesture.
- **Local fallback**: server unreachable → local GPU (auto-pulls missing model).
- **Forced local**: `--local` skips server (requires GPU-feature build; errors gracefully otherwise).
- **Server**: `mold serve` (`--port`/`MOLD_PORT`, `--bind`, `--models-dir`, `--log-format json|…`, `--log-file`, `--gpus`, `--queue-size`, `--discord`). Managed daemon: `mold server start|status|stop` (`--port`, `--bind`, `--models-dir`, `--log-file`). Auth via `MOLD_API_KEY`; CORS `MOLD_CORS_ORIGIN`; rate limit `MOLD_RATE_LIMIT`/`_BURST`. `GET /api/resources` + `/stream` (GPU/VRAM/CPU live), `/api/capabilities`, `/api/status`, `/health`, `/api/openapi.json`, `/api/docs` (Scalar), `POST /api/shutdown`.
- **Cloud provisioning**: the desktop RunPod workspace covers API setup, account/spend status, GPU stock, geographically labeled datacenters, full network-volume lifecycle management (create, select, rename/grow, delete), pod create/start/stop/delete, RunPod console handoff for logs, automatic refresh, and connecting the app to a pod. The volume form only offers datacenters that support persistent volumes. Volume selection persists across app launches and automatically enforces Secure Cloud plus the volume's datacenter. Network-volume pods omit unsupported stop/start actions; deleting their compute instance preserves `/workspace` on the volume. The CLI additionally provides doctor/get/usage and `runpod run` one-shot generation on fresh/warm pods. Lambda provisioning remains CLI-only (doctor/availability/deploy tunneled web UI/status/logs/tunnel/ssh/filesystems/terminate/reset).
- **Interface scaling**: ⌘+/⌘−/⌘0, the native View menu, and Settings → Appearance & app scale the entire webview from 80–130%. The preference persists, and fixed overlays plus custom context menus remain viewport-clamped at every level.
- **Native image clipboard**: right-click Copy image is available from Library tiles, the Library lightbox, and completed Create canvases. Images are copied at full resolution; video copy remains intentionally disabled.
- **MCP server**: `mold mcp [--host]` — stdio MCP for LM Studio / MCP hosts (exposes generation tools; requires running `mold serve`).
- **Upscale** standalone: `mold upscale <img|-> [-m model] [-o] [--format png|jpeg] [--tile-size] [--host] [--local] [--preview]`; `POST /api/upscale` + `/stream`.
- **Self-update**: `mold update [--check] [--force] [--version vX]` (GitHub release, SHA256-verified; bows out on distro `/usr/bin/mold` linker collision).
- **Shell completions**: `mold completions <shell>` (bash/zsh/fish/elvish/powershell) + dynamic model-name completion.

## 11. CLI I/O niceties (carry into desktop where relevant)

- Pipe-friendly: stdin prompt, stdout image bytes when non-TTY; `--output -` forces stdout; `--image -` reads source from stdin. `mold run flux2-klein "cat" | viu -`.
- `--preview` (env `MOLD_PREVIEW`): inline terminal image/animation preview (viuer + Ghostty/Kitty pixel protocol; animates GIF/APNG/WebP).
- First positional disambiguation: matches known model → model, else prompt.
- Batch to files with auto-suffixed names; overwrite warnings; default filenames sanitize colons.
