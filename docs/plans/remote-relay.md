# Remote HTTPS access through an outbound relay

## Goal and reference

Offer optional remote access to an existing Mold machine without inbound ports on that machine. Direct LAN, VPN, and local operation remain available. Clients use an ordinary HTTPS machine URL and existing pairing/API keys. The reference is Zephra `Relay/link/README.md`, `Packages/ZephraLink`, and URandom `modules/zephra/link.tf`: authenticated outbound connections and Terraform-owned AWS infrastructure. Its encrypted room protocol is not reused: API Gateway frame limits, per-message Lambda ordering and custom Swift transport do not fit Mold HTTP uploads, SSE and media ranges.

## Architecture

Introduce a small GPU-independent pure Rust `mold-ai-relay` workspace crate. The existing `mold` binary exposes `relay serve` (cloud gateway) and `relay connect` (machine connector); a lightweight standalone `mold-relay` binary exposes the same commands for cloud deployments without Candle/GPU dependencies.

V1 owns one public machine URL per relay process, `https://mold-link.urandom.io`. One authenticated connector may own it at a time; a second connector is rejected rather than replacing the active machine. This is deliberate: no unrequested multi-tenant account system, wildcard domains or discovery service. Additional machines can run separate relay processes and domains later. Clients may already manage multiple machine URLs.

Caddy terminates public HTTPS and sends ordinary HTTP to a loopback-only data listener. A separate loopback-only Axum listener handles control and data WebSocket upgrades under `/_mold/relay/`. The connector maintains an outbound WSS control connection authenticated with a high-entropy relay enrollment token in the Authorization header. Each incoming HTTP TCP connection gets an unpredictable one-use stream ID and an open notice. The connector opens a separately authenticated WSS data socket for that ID, then connects only to its explicitly configured loopback Mold socket. Binary messages carry bounded chunks of the original TCP byte stream in order, with backpressure. This preserves HTTP methods, status, headers, chunking, multipart bodies, SSE, Range/HEAD, media tickets and the SPA without rewriting URLs or buffering media. Full connection closure tears down both directions; no mutations are replayed after reconnect. Caddy uses a plaintext HTTP/1.1 upstream, disables response buffering, blocks public `/metrics`, and removes spoofed forwarding headers before proxying. The binary stream wire distinguishes directional EOF from whole-session close so upload half-close does not truncate the response.

## Security and lifecycle

This is a trusted HTTPS proxy, not Zephra end-to-end encryption: Caddy and the AWS relay can see API credentials and media. Document this plainly. Enrollment credentials are separate from Mold API credentials, read from owner-only files/env, never CLI arguments or URL query strings. WSS is required outside explicit localhost test mode; TLS certificate verification stays enabled. The connector target must be a numeric loopback address, never a caller-supplied destination. Every new target connection opens and holds its actual loopback TCP socket, then checks unauthenticated `/api/status` returns 401 using a client with redirects disabled; fail closed for unauthenticated hosts, redirects, network errors or unexpected statuses. Do not inject a Mold credential: normal request authentication and device revocation remain owned by the actual Mold server.

Bound pending streams and active connections (default 64), bounded channel/chunk sizes, 15-second attachment deadlines, connection/idle liveness timeouts, ping/pong heartbeats and reconnect backoff. Unknown, expired, reused or cross-session stream IDs are rejected. Disconnect cancels all session-owned pending and active streams. Authentication failure must not be retried rapidly. Gateway admission is bounded; Caddy bounds request/control abuse. Mold sees loopback proxy peers, so any enabled per-IP limits aggregate remote callers and the auth probes; never trust arbitrary forwarded headers to bypass limits. Relay tokens rotate by restarting the gateway/connector; existing sessions terminate. Never log tokens, URLs with credentials, request paths/query strings, headers or payloads. Health reports only gateway liveness and host availability, not secrets. Cloud listener bind defaults to loopback. Run services as unprivileged users with systemd hardening.

## Surfaces

CLI/MCP/Discord use the normal HTTPS MOLD_HOST plus their existing credential mechanisms. Browser users open the HTTPS URL and authenticate with existing UI. Web, Tauri desktop, Tauri iOS/Android and native macOS/iOS add that URL as a machine and pair/use their existing API-key store. The public SPA bootstrap must be readable without an API key; GET/HEAD shell/assets are separated from protected API routes, and the browser must allow supplying a key for its serving origin. Unknown `/api/*` routes remain protected. No transport-specific endpoint allowlists. Existing cross-host media behavior, redirect fencing, instance identity and signed browser media tickets remain authoritative. Native macOS This Mac remains an app-private engine; hosting uses an explicitly started, authenticated `mold serve` instance rather than publishing its private app credential. Clearly document that boundary. Hosts run the connector as an explicit companion process/service; this release does not pretend every GUI automatically hosts a tunnel.

## AWS and deployment ownership

URandom Terraform gains an isolated `modules/mold-relay` module wired from main: small x86 EC2 in the existing default VPC, encrypted gp3 root, IMDSv2, EIP and Route53 A record, only 80/443 public ingress, no SSH, SSM management role, public outbound networking. Caddy ACME manages certificates; DNS/instance are Terraform-owned. Token provisioning happens out of Terraform state/user-data via SSM to an owner-only runtime file. Source artifacts are built/deployed from Mold with an explicit deployment script; Terraform does not replace deployed code. Bootstrap config is nonsecret. Production deploy is user-authorized in this conversation; regenerate/review plan before apply and apply only module-owned resources if unrelated drift exists. No changes to Zephra or NXV routing.

Before applying, verify live profile/account, instance pricing and selected AMI/subnet. Report recurring instance/EBS/IPv4 costs from current AWS prices, with transfer extra. Deployment must verify DNS/TLS, unauthorized control rejection, offline response, temporary authenticated fixture-host traffic and stream correctness. Never expose an actual workstation until explicitly configured with a distinct relay token and Mold authentication. Keep existing services healthy. Rollback stops relay services/removes DNS via reviewed Terraform; do not destroy unrelated resources or secrets.

## Acceptance and known limits

Public URL works with existing HTTPS clients and browser media semantics; unauthorized users cannot access protected Mold routes; gateway cannot tunnel to arbitrary destinations; host can disconnect/reconnect without replaying jobs; secrets stay out of code/state/logs. Deployment proof and each surface proof are recorded separately, with simulator/device gaps explicit. Machine sleep/offline means unavailable, not a cloud GPU fallback. Gateway is a single-instance availability boundary and a trust boundary; no promise of E2E confidentiality, automatic GUI hosting, unlimited traffic or zero recurring cost.
