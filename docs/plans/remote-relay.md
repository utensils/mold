# Lambda remote relay implementation plan

## Goal and architecture decision

The user explicitly requires AWS Lambda like Zephra. This supersedes the EC2/Caddy cloud deployment and its quota request. Keep direct LAN/VPN operation and add a normal HTTPS machine URL on every existing surface. AWS runs no persistent virtual machine. Zephra's canonical reference is `/Volumes/ExternalStorage/Projects/Zephra/Relay/link/` and `Packages/ZephraLink`; URandom owns infrastructure and Mold owns deployed relay code.

CloudFront exposes `https://mold-link.urandom.io` with IPv4/IPv6 and ACM TLS. Static browser assets come from a private S3 origin. HTTP API requests go to a streaming Lambda Function URL. That invocation opens an authenticated internal WebSocket guest connection to an API Gateway WebSocket API. A short-lived router Lambda forwards frames between this guest and the machine's outbound connector, using DynamoDB membership metadata. Responses arrive directly at the HTTP invocation's guest socket: no DynamoDB polling or storage of response chunks. The HTTP invocation parses the original host response and streams it to the caller, then disconnects.

The Rust connector still forwards only to its explicitly selected numeric loopback Mold socket. Every socket must pass the existing exact-socket anonymous `/api/status` 401 probe and persistent framing check before traffic is forwarded. Preserve local HTTP authentication, pairing and revocation; do not inject an operator key. One host owns the gateway at a time. Native macOS This Mac remains private; explicitly start authenticated `mold serve` to host it.

This is a trusted TLS proxy, not Zephra's end-to-end encryption. AWS sees API credentials and staged media. S3 stores temporary transport copies; the local host remains gallery/queue authority. No automatic GUI hosting, cloud GPU fallback or mutation replay.

## AWS ownership and cleanup

Replace only `module.mold_relay` in URandom. Remove its unused EC2 IAM role/profile/three policies, security group, unassociated EIP and A record while creating Lambda/API Gateway/DynamoDB/S3/CloudFront/ACM resources. No EC2 instance or disk was created. Do not alter Zephra, NXV or other existing resources. The opened EC2 quota case is obsolete; stop pursuing it. AWS exposes no quota-request cancellation API; do not send a support message without separate authorization.

Use supported Node.js 22 or 24, never deprecated Node 20. The pinned AWS provider predates newer runtime enums, and aliases cannot select another version of the same provider. Create the two Node.js 22 functions through a narrowly scoped `aws_cloudformation_stack` with inline offline bootstrap code and outputs for their names/ARNs; the AWS provider treats its template as data, so runtime enum validation does not force an unrelated root-provider migration. Terraform owns that stack and all surrounding resources. CloudFormation updates must leave the bootstrap Code property unchanged so configuration updates cannot replace deployed code; verify this with the exact template and tests. If this cannot be verified, use a supported custom runtime instead. Terraform owns function configuration and minimal offline bootstrap packages; deployed code belongs in `relay/aws/` and Lambda code hashes are ignored like Zephra, preventing unrelated Terraform rollback.

Create a private SSE-encrypted temporary S3 bucket, public-access blocks, TLS-only bucket policy, short lifecycle and narrowly scoped object prefixes. CloudFront accesses it through OAC. The Function URL requires IAM authentication with CloudFront OAC; direct unsigned origin requests must fail. CloudFront caching is disabled for API/control responses and never varies away credentials. Every ordinary POST/PUT/PATCH body and staged envelope carries `x-amz-content-sha256` computed by the shared client helpers. CloudFront OAC overwrites Authorization with its SigV4 signature: a trusted viewer-request CloudFront function first strips caller-supplied preserved-authorization headers, copies viewer Mold Authorization into a distinct forwarded header, and removes the original. Restore it only inside the restricted frontend; X-Api-Key is forwarded normally. Preserve query strings; remove untrusted forwarding headers before the local host. Block public metrics at the routing layer and connector defense.

CloudFront signed media uses a trusted public-key group. Generate its private key outside Terraform, keep it only in a protected local file and SSM SecureString; Terraform receives the public key only. Enrollment and internal frontend admission tokens are distinct, provisioned outside state/user-data. Host receives only its enrollment token. Router validates role-specific tokens from a narrowly scoped SSM parameter. Frontend can read only its own internal token and signing key. Never put tokens in URLs, invocation logs, command output or repository files.

IAM grants router only membership table operations and ManageConnections on its own API/stage. Frontend grants only its own admission/signing parameters, temporary S3 prefixes and transfer metadata. No wildcard parameter reads. Reserved Lambda concurrency and API Gateway throttles bound public cost/admission. Function log groups have explicit retention, with no request headers, URLs/query strings, payloads, API keys or signed grants logged. Operational logs contain only nonsecret IDs, byte counts and outcomes.

## Ordered reliable WebSocket transport

Reuse the Zephra short Lambda invocation/message-routing pattern, not its lossy gap-skipping inbox: skipped byte frames corrupt HTTP. API Gateway supports text frames only. Each envelope carries version, session epoch, request ID, direction, sequence, cumulative acknowledgement and base64 payload. Cap decoded payload at 16 KiB and serialized JSON comfortably below 32 KiB. Use a bounded credit window (initially four frames), bounded out-of-order storage, digest-matching duplicate suppression and retransmission only within the same request/session. An unresolved gap, conflicting duplicate, reconnect or stale epoch terminates the request. Never resubmit a mutation on a replacement connection.

Control/ACK frames have priority and a shared sender budget below the API throttle. Directional EOF preserves half-close; duplicate EOF/data-after-EOF is rejected. Cancellation tears down both sides. Heartbeats update short membership leases and do not extend application idle deadlines. Rejoin before API Gateway's two-hour cap. `$disconnect` conditionally clears only the current epoch. DynamoDB TTL is garbage collection, never authorization: explicitly check expiry. Use strongly consistent primary-key membership lookups rather than eventually consistent indexes.

Admission is conditional and bounded to 32 active frontend requests per host, allowing several SSE streams plus ordinary calls. No eight-guest Zephra limit. Lost-disconnect cleanup must reclaim expired guest leases without deleting a newer host epoch or leaking capacity. Offline/busy hosts return explicit 503, not a hanging HTTP request. Unauthorized enrollment returns 401/403 and is not retried indefinitely. Existing local gateway code may remain as a documented self-hosted development transport; production connect must explicitly select the AWS wire rather than infer it from an untrusted response.

## AWS payload and lifetime limits

A Function URL buffers its incoming invocation event, limited to 6 MB; binary base64 expansion reduces usable body size. Streaming responses are limited to 200 MB, have a 2 MB/s cap after the first 6 MB, and Lambda runs at most 900 seconds. A transparent byte proxy alone cannot meet all Mold surfaces. Use a conservative 2 MiB ordinary request threshold and the generic staged-transfer contract below. The existing Mold server request-body limit remains 64 MiB; the relay does not silently raise it.

Terminate streaming frontend requests deliberately before 840 seconds, with periodic SSE keepalive bytes where the actual stream allows them, and let consumers reconnect/reconcile. Do not inject bytes into arbitrary binary responses. CloudFront response-read timeout must accommodate actual keepalive gaps; response-completion timeout must be unset or longer than the deliberate stream lifetime. Verify deployed settings and a stream longer than normal CDN defaults.

Synchronous generation can wait silently for more than one invocation. Rust client relay mode uses existing durable batch admission, client-ID lookup and status/output retrieval instead of holding `/api/generate` open. Streaming generation retains the admitted job ID and reconnects to its events/status after graceful EOF. Native/web already use durable generation but every EOF consumer must be checked; a deliberate EOF must not permanently disable updates. Compatibility endpoints cannot promise unbounded synchronous external curl calls; document durable queue use for such clients. Never call generation twice to recover a timed-out response.

## Generic large request contract

Shared Rust, TypeScript and Swift HTTP helpers must stage _any_ body over 2 MiB, including JSON/base64 and multipart, before a Function URL sees it. Preserve original method, percent-encoded path/query, headers, content type, byte length and SHA-256. File-backed uploads must not be copied without a bounded limit. Direct LAN/VPN hosts keep the existing code path. Relay discovery is additive through a small same-origin `/_mold/relay/info` contract or a trusted response header, with explicit protocol version and limits.

Prepare a transfer through an authenticated same-origin relay endpoint. Before granting S3 writes, forward the caller's Mold credentials to the host's authenticated status check; unauthorized callers receive no upload grant. Bind transfer metadata to original request, host epoch, caller credential digest, expected length/hash, short expiry and a random object key. Presigned PUT grants authorize only that object and declared integrity metadata; clients never forward their Mold key to S3. Enforce object size/integrity at consumption as well as preparation, bounded pending-grant count and lifecycle cleanup. No arbitrary URLs, buckets, keys or SSRF destinations supplied by callers.

After upload, submit a small request envelope. Conditional consumption is single-use for mutation bodies and rejects expired, mismatched or reused grants. Host retrieves only the server-minted object, validates size/hash before local submission, streams its bytes to the original local request and deletes/retires the temporary copy. Failed upload or validation submits no local mutation. Do not automatically replay after ambiguous completion. Multipart bytes and headers are preserved, not reconstructed from guessed fields.

## Large response, media and range contract

Decide response mode before emitting any viewer headers or body. Known finite Content-Length above the safe threshold stages immediately; finite unknown-length responses spool once to bounded temporary S3 storage before an envelope is returned. Explicit text/event-stream responses remain streaming with the 840-second deadline. Do not reissue the original request, especially mutations, to obtain its response. Normal small responses stream through the frontend. Responses that exceed a safe threshold use an explicit object envelope with original status/headers and a same-origin signed CloudFront URL; keyed clients must never rely on a 302 redirect. Generic response helpers fetch the authorized object without Mold credentials and reconstruct original status/header semantics for consumers. Validate HTTPS, exact serving origin and reserved object prefix; reject arbitrary cross-origin URLs. This covers raw media, retained media, exports, thumbnails/assets and downloads that bypass media-token.

For native players/browser video and GLB, extend `/api/gallery/media-token` relay responses with an optional validated `url` and readiness state. Existing token-only direct servers remain compatible. Update web gallery media, shared desktop/mobile media and Swift `MediaToken`; all currently synthesize the original URL from token. Authenticate the original local media request before staging bytes. Large staging is asynchronous: return bounded pending identity and poll readiness rather than exceed native ten-second request timeouts. Staging may reuse a file generation/mtime/length identity within its grant scope, but never expose a revoked credential's new grant or make cloud storage the library authority.

CloudFront/S3 supports ordinary Range/HEAD and content disposition. Signed URLs have explicit expiry; renew resolution for later playback/seek after expiry. Temporary object retention must exceed grant lifetime while signed access expires independently. Integrity, cancellation and orphan cleanup are tested. A full file does not pass the Lambda response size ceiling; range downloads do not bypass authentication through public object paths.

## Client seams and surface coverage

Rust: `mold-core/src/client.rs` and generic request helpers, multipart/raw bodies, durable generation facade and event reconnection. CLI, MCP and Discord inherit the normal HTTPS client. TypeScript: `studio/api/client.ts`, raw web fetch helpers, EventSource adapter, uploads and gallery media; Tauri desktop/mobile share these. Swift: shared `HTTPBackend+Transport` send/file upload, `SSEStream`, event consumers, retained-media downloads and `MediaToken`; native macOS/iOS use the shared package. Audit every bypass of generic helpers before declaring parity. No per-model allowlists.

Keep normal machine URL/pairing UX. Browser shell is served statically even when the host is offline; authenticated API requests clearly report offline. Hosting remains an explicit authenticated server plus connector. Cross-origin redirects with keys remain refused; explicit signed object handoffs do not weaken that rule.

## Independent plan review disposition

Independent sub-agent approved the architecture after three blocking corrections: OAC payload hashing and trusted Authorization preservation; selecting staged response mode before writing headers without replaying the request; and eliminating impossible per-alias provider versions. All three are incorporated above. The Node.js 22 function-only CloudFormation stack is the explicit runtime compatibility mechanism; its code ownership and deployed configuration must be verified.
