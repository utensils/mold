## Transport constraints confirmed

`studio/api/queueSourceThumbnail.ts` enforces 2 MiB image previews. `crates/mold-server/src/queue_input_thumbnail.rs` lists exact manifest indices and serves only 320px rendered previews. Keyframe sealed members wrap an image in JSON and need existing role-aware extraction. The added original queue input route returns full-sized submitted pixels; these may already be canvas-fitted and are not a promise to recover the pre-fit authoring upload. Retained gallery originals already have exact-member content APIs and authenticated resource leases. Native inspection preserves full pixel geometry up to 32 Mi pixels (about 128 MiB at 8-bit RGBA, plus decoder overhead and transient buffers); larger images fail with an explicit size message while reuse remains available. Filenames, source digests alone, another fleet copy's member ID, thumbnail URLs, and fitted submit snapshots are not substitute original authority.

This inventory is file-backed and cross-checkable. The implementation reviewer repeated image/video/audio/file-control searches within these consumers and found no uncovered input visualization.

## Review sequence

A planning subagent produced the file-backed inventory and plan. A separate subagent cross-checked both before implementation, adding Share Inbox coverage, identity wrappers, submitted-input terminology and picker authority/focus requirements. A third subagent implemented the plan with bounded native, browser and server work. Independent implementation review found four issues (native pixel budget, picker authority revocation, Queue keyboard integration and Android touch targets); all were fixed with regression tests and independently re-reviewed with no remaining blockers. Exact-head CI must pass before merge.

## Runtime evidence (2026-10-11)

Disposable loopback fixtures refuse every mutation. Chromium web picker inspection fetched a 900×1600 original instead of its 180×320 thumbnail; Fit rendered 283.5×504, Actual size rendered 900×1600 with scrolling. Escape returned focus to View original and left the picker and source sheet open; closing the picker preserved its previous attachments. Actual Safari repeated picker View original, Actual size and Escape with selection still off. After explicitly attaching one reference, View original and Done preserved its filename, ordinal, canvas label and remove/reorder actions. Native Mac repeated Library picker View, Fit, Actual Size and Escape without selection. After explicitly attaching the reference, View and Done preserved the reference ordinal, canvas label and removal control. Native iOS Simulator (iPhone 17 Pro, iOS 26.5) repeated picker View/Done without attachment, then explicit attachment and View/Done preserved image 1. Both final native builds passed. Physical iOS/Android devices have not been tested. Actual Tauri WKWebView Queue row View input showed the full Source image with Actual size and Escape returning to the same queued job. Machine Queue details exposed all three indexed inputs (image, video and audio), including nonimage placeholders. Video and audio played with a verified 2-second duration; Done returned focus to the respective View input control and kept the Queue detail open. No generation request was sent; the fixture rejected estimate requests and every mutation. Native32-Mi-pixel refusal, captured-route revocation and file cleanup have regression test evidence; physical iOS/Android and Tauri mobile runtime remain untested.
