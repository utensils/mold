Mold Studio — Interface Spec

A single design system across five surfaces for a local, no-cloud diffusion studio. This document is the source of truth for the simplified UI: its principles, tokens, shared components, information architecture, and the flows an implementer should complete without drifting from the system.

Product: mold · local image + video generationSurfaces: macOS · iOS · Web · Mobile web · Terminal (TUI)Status: prototype → build handoff
North star
Dead-simple by default; power on demand. A newcomer can type a prompt and press Generate without meeting a single advanced control on simplified shells; tablet-and-wider web deliberately keeps Advanced visible as its power surface. Everywhere else, depth is progressively disclosed until asked for. One shared component vocabulary drives every surface, so the product feels like one tool wearing five native shells — four graphical and one terminal — never a web app bolted onto a desktop frame.

01 Principles

Simplicity first
The primary path — describe, choose a look, generate — is always one screen with no scrolling to essentials. If a screen feels empty, that is correct, not a gap to fill.
Progressive disclosure
Advanced capability uses one clearly-labelled, surface-appropriate entry (inline toggle, sheet, or accordion) with no redundant nested disclosure. Tablet-and-wider web is the intentional power-surface exception and keeps the same icon sections visible.
One system, five shells
Identical tokens, components, copy and state. Each surface only changes chrome and layout density — not vocabulary. The terminal reads the same vocabulary rendered in a monospace cell grid.
Shared source of truth
Prompt, model, settings, theme and library are one state. An edit on any surface reflects on all; components read the same bindings.
Contained, not global
Every overlay (drawer, sheet, lightbox, palette, modal) renders inside the frame it belongs to — never a page-level layer that escapes its window.
Local-first voice
Terse, lowercase, technical, dry. Reinforce "runs on your machine" everywhere it's true. No cloud, no Python, no fuss.

The four palettes and the type / space / motion scales must live in one shared source — a tokens.css of custom properties (or JSON compiled to it) — imported by both the app and this spec. No screen hard-codes hex; a new theme is added by extending the token set, never by editing components.

05 Surfaces & containment

Each surface is a real device/window frame with overflow:hidden and its own positioning context. Overlays render inside their owning frame (position:absolute within the frame), keyed by a surface token — desktop d, web w, iOS i, mobile web mw. There is no page-level fixed overlay. The logo (3D orb mark) sits in the page header, sidebar header, and both web bars; the wordmark is always set separately in display bold.

Terminal surface (TUI)

The fifth shell runs in the terminal (mold tui, built on ratatui). It is a translation, not a port: the same five workspaces, dual-accent role model, progressive disclosure and command palette, re-expressed in a monospace cell grid — flat planes (no shadow, 0 radius), box-drawing panels, and focus-by-border-color. Number keys 1–5 switch workspace; ⇥ cycles panel focus; ^K opens the palette; A expands Advanced; a one-line activity strip above the status bar carries live job · throughput · queue depth. Parameters show four essentials with the six Advanced sections as a terminal-specific collapsed accordion list, preserving vertical space in the cell grid.

Accents map straight across: safelight → primary / focus / selection, halide → info / live / spinner. The four Studio themes ship as TUI presets — Studio Dark, Studio Light, Safelight Dark and Safelight Light — plus Catppuccin Mocha retained as the single-blue baseline the TUI ships today — added to theme.rs alongside the existing seven. Braille spinner and ✓ / ★ / • glyphs stay the shipping vocabulary; no emoji.

Recommended TUI stack
Stay terminal-native on ratatui — do not port to a webview; being in the terminal is the point. Layer four crates to close the feel gap with the graphical surfaces: tachyonfx add for the Studio's motion vocabulary (workspace fades, activity pulse, generation shimmer — the biggest single upgrade); ratatui-image keep (already wired for Kitty / Sixel / iTerm2) for real thumbnails in Library and the inline Create preview; tui-textarea keep for the prompt; tui-scrollview + tui-widget-list add for smooth Library-grid and Timeline scrolling. Gate all motion behind a reduce-motion setting.

06 Key flows

Generate

Empty canvas ("Your print develops here") → press Generate (or ⌘↵) → progress ring with stage + percent → result with caption (model · seed · time · host). Estimate shown before running. The activity strip mirrors the running job and any queued jobs (cancellable) so progress is legible without leaving Create. The strip is present tense: it mirrors the running job and any queued jobs (cancellable), holds a failed job briefly so it can be resumed or dismissed, and collapses everything else into a count that opens History. (The archived prototype's strip was always live-only — settled rows were never designed into it.)

Make a sequence (v0.14)

Mode is a setting, not a place. There is no Single | Sequence switch and no separate page: Output (One shot | Sequence) is a control in the Create settings column, beside Model. Choosing Sequence filters the model picker to sequence-capable installed video models (auto-picking one and remembering the single-mode model for the way back), turns the composer into a clip rail — clip pills joined by seam pills — and relabels the primary button Generate sequence. New clips default their frames from the model's own server-advertised default, not a hardcoded constant. The seam pill names its transition in words (Smooth / Cut / Fade 8f, zero-tail joins say Join) with a mini diagram as reinforcement; clicking it opens the seam editor — three teaching rows plus the fade-length stepper — as a popover on desktop/web and a bottom sheet on iOS. Switching Output back to One shot keeps clip 1 as the prompt and parks the other clips; nothing is erased. Sequences submit as durable jobs and render in the same activity strip as prints (queued/running, watch, cancel, resume). A settled sequence leaves the strip: its video lands in the canvas with Edit sequence and Show in library, its print is in the Library carrying every clip's prompt, and its job record is in Library ▸ History ▸ Sequences, which is also where Clear inactive and Clean up disk live. A settled sequence can be edited in place: its clips reload into the rail, clip pills show which clips are cached (✓) versus will re-render (↻) as you edit, and Update sequence re-renders only from the earliest changed clip — transition-type and fade-length edits re-finalize with no re-render at all. From a sequence print in the Library, Reuse settings starts a fresh sequence from the recorded clips (saying how many it restored and naming anything a print does not record); Edit sequence re-enters the original job with its cached clips, checked once on click — a job that is gone falls back to reuse and says so, while an unreachable machine changes nothing.

Prompt expansion

Batch = 1: one-tap rewrite that enriches the prompt in place with a visible undo. Batch > 1: generates editable variations to review, edit, and queue. Never silently overwrite the user's words.

Style & Advanced

Style is a single collapsible chip row, deselectable. Advanced is one entry per surface with capability-gated, always-open icon sections: Scheduler & sampling (default / ddim / euler-ancestral / unipc + CFG rescale), Negative prompt (with quick-adds), Source image (denoise strength · fit · inpaint mask), LoRA stack (add + per-adapter weight), Upscale after generate (Off or Real-ESRGAN), Output & seed (format · seed mode), plus family-specific Video and GPU placement sections. There are no nested section disclosures; an active-count badge shows how many advanced options are set and Reset clears them.

Surface split (v0.13): the web app at tablet width and above is the power surface — Advanced renders inline as an always-visible column in the Create controls region. Mobile web keeps the same icon sections in its phone sheet. The desktop app deliberately stays simplified until its single Advanced toggle is opened; then the same always-open icon sections extend inline below the essentials in the existing resizable settings inspector, preserving the canvas and avoiding a second overlaying panel.

Library, Models, Machines

Library: grid/feed with all/images/video filters and search; web and desktop place a persisted Lightroom-style small-to-large thumbnail slider in the top toolbar; opening a print uses a desktop/web lightbox (image + metadata + Reuse settings, plus Edit sequence on a print a durable sequence produced) and a phone full-screen viewer (position counter, reuse, save). Models: installed/discover; every card, table row, installed row, and detail surface repeats a neutral model-kind badge. Mature entries add the textual danger badge 18+ NSFW (never color alone). A row opens detail (drawer/sheet) with family, modality, kind-specific weights/footprint, components, variants, and any available description, tags, source, license, format, or popularity; absent catalog metadata is omitted rather than replaced with filler. Machines: host cards with live telemetry open a detail view (GPU load, memory, temp, queue, uptime, loaded & installed models, set-as-target); + Add machine opens the stepped connect modal (type → details → connected).

System affordances

⌘K palette for navigation and quick actions. Downloads center (Downloading / Queued / Recently installed). Sidebar collapse for focus. Persistence: theme family, appearance, sidebar state, and active workspace/route restore on launch (localStorage).

07 Content & voice

  • Product name mold always lowercase; commands lowercase mono (mold run, mold pull flux-dev:q4).
  • Section titles Title Case; table headers UPPERCASE; status values lowercase (loaded, ready, developing).
  • Model ids as family:variant. Units tight: 6.9 GB, 18.4 MiB/s, eta 6m 12s.
  • Feedback glyphs only: ✓ done · ★ loaded · • info. No emoji in product UI. Error copy is blunt and short.

Adherence checklist for any new UI
  • Does the default path stay one screen, with Advanced secondary to the composer and hidden on simplified shells?
  • Is new depth behind one surface-appropriate entry (inline toggle / sheet / palette) without redundant nested disclosure?
  • Is it built only from the shared components, referencing tokens (no new hues, no hard-coded hex)?
  • Does it read from shared state so all surfaces stay in sync?
  • Does any overlay render inside its own frame?
  • Is the copy terse, lowercase, technical — and emoji-free?

10 The Develop — signature element (carried forward)

Every generation is visualized as a print developing: a deterministic grain field, seeded from the job's actual seed, that resolves in lockstep with real DenoiseStep SSE events. This is the canvas treatment behind (and around) the §06 progress ring on surfaces that implement it (desktop today; other surfaces may adopt the shimmer-only fallback). It is client-side and truthful about what it knows — there is no server-side preview-frame stream.

  • Latent (queued): static, coarse, cold monochrome grain (halide-tinted) from a hash-noise shader seeded with seed — every job's grain is unique and reproducible.
  • Developing (running): on each DenoiseStep {step, total}, grain amplitude and correlation length ease down with step/total; tint warms from halide toward safelight. The step counter ticks as 12/28 in mono.
  • Fixing (complete): the final image crossfades in under the last grain frame (450ms) with a brief warm cast that neutralizes (300ms).
  • Failed: grain freezes and desaturates to stop-tinted — a failed print is still an object you can inspect and retry.
  • Scale-invariant: the same shader runs at hero, chip (48px), tile (96px), and badge (16px) sizes.
Restraint budget
The Develop is the only animated/atmospheric element beyond §09's shimmer and transitions. Everything else stays quiet and matte.
