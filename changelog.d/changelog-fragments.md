- **Release notes now live in per-PR `changelog.d/` fragments instead of a shared `[Unreleased]` section.** Every open pull request used to insert its note at the same line of `CHANGELOG.md`, so whichever PR merged second conflicted and lost its CI. Each PR now adds `changelog.d/<slug>.md`; `scripts/release/sync-release-pr.sh` assembles the fragments under the new version heading on the release PR (newest first) and deletes them, and a new advisory `changelog` CI check refuses direct `[Unreleased]` edits, lints fragment shape, and asks for a fragment when shipped source changes (`skip-changelog` label opts out). release-plz is untouched: it never read `CHANGELOG.md` (`changelog_update = false`), and the trusted release-PR file-scope check now permits the bot's fragment deletions.
